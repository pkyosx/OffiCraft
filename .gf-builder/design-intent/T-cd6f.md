# Design Spec — T-cd6f

confidence: high — placement and behavior are grounded in the current
`ThemeSettings`, member detail, worker detail, theme import/export, REST, SSE,

**Where** — Pool management stays in Settings → Theme management → Edit theme,
where the owner already changes theme images. A member's selected index stays
beside their identity in the existing member/worker detail card, where the owner
already edits that actor.

On a narrow viewport, every pool item wraps into two rows: preview + index on
the first row, labeled actions on the second. Ordering is never drag-only:
Move up / Move down buttons keep the operation keyboard and touch accessible.

**Flow** — Open a theme → add/replace/reorder/remove pool images → Save theme →
open a member/worker detail → edit the persistent non-negative index → Save →
the correct SSE topic refetches every avatar surface.

**Key decisions**

- Keep pool editing in the existing theme editor and index editing in the
  existing identity card. This follows A1 (moment of need) and A2 (reuse the
  product's established theme/identity surfaces) instead of creating a separate
  avatar administration page.
- Model pools separately as `avatarPools.member` and
  `avatarPools.outsource`, while leaving `avatars.owner` and
  `avatars.assistant` as single strings. This keeps the user's model visible
  in the data shape and prevents the implementation detail from changing
  owner/assistant semantics (A1).
- Preserve old bundles by accepting `avatars.member` /
  `avatars.outsource` singleton strings, moving them into one-element pools,
  and emitting only the canonical new shape. Compatibility has one direction
  and one source of truth; there is no permanent dual rendering precedence.
- Resolve a non-empty pool as `pool[avatarIndex % pool.length]`; resolve an empty
  pool as the built-in glyph. Theme switches and pool shrinkage are visual
  reads, not hidden database writes, so an appearance change never silently
  edits identity state (A1).
- Use explicit Move up / Move down controls instead of drag-and-drop. Reordering
  is an occasional settings operation (P8), and buttons preserve discoverability
  and keyboard/touch operation without a second interaction model.
- Replace/remove/reorder are staged inside the existing theme form and commit
  only with its Save button. Cancel restores the prior pool as a whole; no
  confirmation modal is added because these edits are reversible without
  losing unrelated saved work (P3).
- Cap each member/outsource pool at 12 images. Every image retains the existing
  strict raster gate (PNG/JPEG/WEBP, strict base64, matching magic bytes,
  decoded ≤64 KiB); the count cap bounds the JSON setting and the editor.
- Remove the personal-avatar editor and binary endpoints rather than retaining
  a hidden personal-over-theme path. Migration deletes each referenced `ava-`
  blob before dropping `avatar_attachment_id`; rollback restores only an empty
  legacy pointer column because deleted personal bytes cannot be reconstructed.
  This irreversible cleanup is called out explicitly in the owner gate.
- Add a dedicated owner-only avatar-index update seam shared by staff and
  outsource instead of widening the staff lifecycle PATCH to worker rows. This
  respects the existing API boundary while keeping one visual-identity operation
  for both actor kinds (A2 with its existing-boundary precondition checked).
