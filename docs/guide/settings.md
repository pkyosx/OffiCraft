# 設定與參數

工作室的所有設定集中在一個地方：頂列的 **⚙️ 齒輪 › 設定**。這份帶你逐一看過五個子頁，以及最容易被找的 **參數調整**。

> **選**用哪個主題、語言、改密碼這類個人偏好在**頭像下拉 › 偏好設定**，不在這裡。唯一例外是**主題的「管理」**（新增／編輯／匯入／匯出）——它放在設定頁的「主題」子頁（見下）。簡單記：**偏好設定選主題，設定頁管理主題。**

---

## 設定的五個子頁

點頂列 **⚙️ 齒輪** 打開設定，左側有五個子頁：

| 子頁 | 放什麼 |
| --- | --- |
| **系統更新與備份（System update & backup）** | 目前版本、檢查與升級、接收 Beta、自動更新開關、備份健康 |
| **角色誌（Role journal）** | 每個角色的定義（Duty）、**判準（Insight）**、累積的學習經驗（Learning），以及三塊「全域情境」 |
| **任務手冊（Task manuals）** | 每一「類」任務的作業手冊（用途、要哪些欄位、SOP、負責誰） |
| **參數調整（Parameters）** | 登入有效期、自動換手門檻、監控刷新間隔、文件字數上限 |
| **主題（Theme）** | 管理主題：新增、編輯顏色與用語、匯入、匯出、刪除。詳見 [主題（外觀與用語）](theme.md) |

---

## 系統更新與備份

**升級不必重跑安裝腳本。** 這一頁就是你日常升級 OffiCraft 的地方：

- **目前版本** — 這台 server 現在跑的建置身分。
- **檢查更新** — 直接問 GitHub Releases 有沒有新版；有的話一鍵升級（下載 → sha256 驗證 → 原地抽換重啟）。
- **接收 Beta 版本** — 打開後也吃 GitHub 的 prerelease。**預設關閉。**
- **自動更新** — 打開後在背景自動升級，不用你手動按。**預設關閉。**

- **備份健康** — 排程備份現在是不是還在產生還原點：綠＝新鮮、紅＝出事（從來沒跑過／太舊／這次失敗，並寫明壞了多久）、灰＝還不知道。**灰色不是「大概沒事」**。

server 升級後，機器上的 warden 與 ocagent 也會跟著自我更新。完整的更新機制見 [架構與運作原理](architecture.md)；從頭安裝／升級／移除見 [安裝、升級與移除](install.md)。

## 角色誌

每個角色一塊，這裡看得到、改得動：

- **角色定義** — 這個職位是誰、負責什麼、遵守哪些規矩。你可編輯——改了它，這個角色的成員下次開機就讀到。
- **判準（Insight）** — 這個角色反覆用到的取捨與界線，跟學習經驗**分開的一份**，由該角色的成員自己搬進來；上線時是空的。
  ⚠️ **Insight 目前不是私有的，只是分開的。** 任何已認證的成員都讀得到任何角色的 Insight；這一版只讓它成為獨立的一塊，**沒有讓它變成秘密**。**寫**才有限制：只有該角色自己的 agent 與 admin 寫得動。
- **學習經驗（lessons）** — 這個角色累積下來的教訓，由成員結案時自動回寫，**同一角色的每個 session 共享**。
- **三塊「全域情境」**（每個成員開機時被注入的開機說明）：
  | 區塊 | 誰能改 | 是什麼 |
  | --- | --- | --- |
  | **系統互動** | 唯讀 | 系統給的通用開機內容（怎麼跟大家互動、用哪些工具） |
  | **使用者自訂** | **你可編輯** | 補上你這間工作室的規矩：你是誰、專案在做什麼、哪些事不能碰 |
  | **啟動程序** | 唯讀 | 開機當下依序做的步驟 |

> **「使用者自訂」是你最該花時間的一塊。** 把「你是誰、專案在做什麼、預算多少、哪些 repo 絕對不能動」寫進去，成員每次開機都讀得到，你就不必每次重講。這正是 OffiCraft 相對「開一堆終端機各跑一個 Claude Code」最省事的地方——詳見 [建議用法](best-practices.md)。

新增／刪除角色（＝多請或裁掉一位正職）的做法，見 [成員與外包](members.md)。

## 版本紀錄（改壞了可以退回去）

上面這些可編輯的長文——**使用者自訂的全域情境、角色定義、學習經驗，以及任務手冊的 SOP 與學習經驗**——每一次被覆寫，系統都會把**被取代掉的那一版留下來**，最多保留三版。

**入口在編輯模式的按鈕列裡。** 按下那一段的「編輯」之後，同一排按鈕上就多一顆「版本紀錄」——它站在原本「重置」的位置，而且**取代了重置**（重置已經沒有自己的按鈕，去處見下）。所以版本紀錄**只在編輯模式下看得到**，而且**按下去才會去拿資料**；在哪一個編輯器裡按，開出來就是那一份文件的歷史，不會有「這是哪一段的版本」的疑問。

打開後是一份**挑版本用的清單**：每一列只有**什麼時候被取代掉的**、以及**是誰把它取代掉的**（顯示「名字（代號）」；已解僱的成員或已釋出的外包名冊上查不到名字，就只顯示代號）。**列上不預覽內容**——內容在點進去之後才佔滿整個面板，免得好幾份長文擠在同一張清單上，要捲很久才找得到你要的那一版。唯一的例外是還原不回去的版本，那個原因會在點進去之前就寫在列上（見下面的字數上限）。

**有預設值的文件，清單最後會多一列「初始版本」——那就是現在的「重置」。** 它排在最後，因為它是這份文件最早的樣子，而清單是新的在上面；點它跟還原走同一個確認框，確認後文件就退回出廠預設。**沒有**預設值的文件（你自己新增的角色、任務手冊、學習經驗）不會有這一列，它們沒有可退回的原廠內容。

**點一列會打開那一版**：預設看到的是那一版**排版後的內容**，右上角可以切換成**與目前存檔內容的差異**——像 git 一樣逐行標出哪幾行被加了、哪幾行被刪了（差異是拿原始文字比的，所以會看到 `##` 這種符號本身）。比的對象一律是**伺服器上目前存著的內容**，不是編輯框裡還沒存的草稿。**還原**也在這裡按（看完再決定要不要覆蓋回去；還原本身也算一次寫入，所以當下那一版同樣會被留起來，你可以再退回來）。

任務手冊的 **SOP 與學習經驗各自有一條版本序列，互不干擾**：改 SOP 不會佔掉學習經驗的三個保留名額，反之亦然，還原也只還原那一欄。**用途與識別鍵不留版本**——改它們不會產生任何可還原的版本。

**這件事有四個邊界，先知道比較好：**

- **只涵蓋「編輯」，不涵蓋「刪除」。** 整份刪掉一個任務手冊或一個角色時，**它的版本紀錄會跟著一起刪掉**——刪除就是刪除，不會有一份還讀得到的殘影留在系統裡，但也因此**還原不回來**。要清掉一份手冊或一個角色之前，自己先留一份。
- **第一次自訂一份原本用預設值的文件時，只會有兩版可退**——它在被你改之前沒有「你的版本」可留，那不是一個版本，是預設狀態。
- **學習經驗、手冊 SOP、手冊學習經驗各自有一份字數上限**（預設一萬字，可在 [參數調整](#參數調整) 調高；全域情境與角色定義沒有上限），而且**超過上限的舊版本，在文件變短之後就還原不回去了**（規則是超標只能往下縮）。這種版本在清單上會標成「無法還原」並寫出原因——它**看得到但按不下去**，不是介面壞了。
- **保留三版是最近三次覆寫**，更早的會自動淘汰。真正重要的東西不要只靠它。

## 任務手冊

每一「類」任務的標準流程（SOP）：這是什麼任務、要哪些欄位（哪個是必填、哪個當識別鍵）、該怎麼做，外加累積的學習經驗，以及**指派給誰**（常駐成員或外包、跑幾份）。

手冊由你建一次、跨任務長期存在，而且**愈用愈準**——每張結案任務都把教訓回寫進同一本。手冊怎麼建、識別鍵怎麼挑，有一個完整例子在 [任務是怎麼運作的](tasks.md)。

> **手冊「由誰負責」只有你（owner）或你的 admin 助理能設。** 那是治理面的設定，一般成員改不了。

## 參數調整

四個伺服器層級的開關：

| 參數 | 是什麼 | 可選 |
| --- | --- | --- |
| **登入有效期（Session length）** | 登入後多久需要重新輸入密碼 | 12 小時 / 24 小時 / 7 天 / 30 天 |
| **自動換手門檻（Auto-handover threshold）** | 一個成員的記憶用到這個比例，就自動把工作交接給新一手 | 40–90% |
| **監控刷新間隔（Monitoring refresh interval）** | 連續監控事件之間，監控頁最多多久刷新一次 | 1–60 秒（預設 5 秒） |
| **文件字數上限（Document size cap）** | 學習經驗、任務手冊的學習經驗與 SOP，每一份各自的字數上限 | 10000–100000 字（預設 10000） |

**自動換手門檻**是這幾個裡比較值得理解的：成員的記憶（context）是有限的，用到門檻就會自動 checkpoint、收尾退場，server 原地重生一個新的它接著跑——你察覺不到接縫。門檻調低＝換手更勤、記憶更清爽但接手更頻繁；調高＝跑得更久才換。多數情況預設就好。（你也可以在成員面板按 **Refocus** 手動觸發一次換手，見 [成員與外包](members.md)。）

**文件字數上限**擋的是另一件事：agent 每次結案會把學到的東西寫回學習經驗，這個上限逼它們「整理」而不是「一直往後貼」——超過上限而且沒有變短的寫入會被整份擋下。**下限就是出廠預設，所以這個值只能調高、不能調低**：調低會讓現在合法的文件立刻變成只能越寫越短。已經超過上限的舊文件不會被截斷，但它的下一次更新只能變得更短。另外，agent 讀一份學習經驗或任務手冊時，回應會直接附上「這份現在多少字」與「目前上限多少」，所以它在動筆前就知道要整理多少，不必等寫下去被擋才發現。

## 順帶一提：偏好設定在哪

**選主題、語言、改密碼**在**頭像下拉 › 偏好設定**：

- **主題** — 在這裡**選**要用哪個主題（內建的辦公室，或你已建立／匯入的自訂主題）。主題換的是顏色與用語、不動版面，也**不蓋過語言**。**新增／編輯／匯入／匯出**主題在設定頁的「主題」子頁——完整說明見 [主題（外觀與用語）](theme.md)。
- **語言** — 介面語言。
- **改密碼** — 換 owner 登入密碼。

頭像下拉裡還有**姓名**（可直接改）與**登出**。
