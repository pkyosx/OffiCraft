# 設定與參數

讀完這頁，你會知道設定的六個子頁各管什麼、參數調整頁上每一格的範圍與預設值，以及哪些設定不在設定頁、要去哪裡找。

## 打開設定

按頂列的齒輪。設定首頁是六個入口，由上到下：系統更新與備份、全域情境、角色誌、任務手冊、參數調整、主題。點進子頁後，用頁頂的路徑回到上一層。

## 不在設定頁的設定

- **主題、語言、版面、顯示應景主題** — 頭像選單 › 偏好設定。偏好設定只負責選用哪個主題；新增、編輯、匯入、匯出主題在「設定 › 主題」。
- **通知信箱** — 頭像選單 › 通知信箱。推播通知要先填這一格才能開啟；這個信箱會提供給瀏覽器的推播服務，請用可以公開的信箱。開啟推播是頂列的鈴鐺按鈕，每台裝置各自開。
- **密碼、兩步驟驗證、通行密鑰** — 頭像選單 › 帳號安全，見 [保護你的工作室](security.md)。
- **外包同時雇用上限** — 辦公室分頁 › 外包頁籤 › 招攬新成員，打開「外包上限設定」。可設 0 到 20 位或「無限」，預設 3 位；設為 0 會暫停指派外包。
- **定期訊息、回呼端點** — 成員詳情，見 [每天固定做某件事](schedule.md) 與 [讓外部事件自動送給成員](webhook.md)。
- **密鑰** — 密鑰分頁，見 [把帳號金鑰交給成員用](secrets.md)。

## 系統更新與備份

畫面由上到下：

- **目前版本** — 這台伺服器正在跑的版本。旁邊是「檢查更新」與「查看 release」；有新版時出現「升級到最新版」，升級完成後伺服器會自動重啟，頁面會自動重新載入。狀態寫「尚未確認最新版本」代表伺服器啟動後還沒成功連上 GitHub 查過，不代表已是最新版。
- **更新設定**
  - **接收 Beta 版本** — 關閉時只看正式 release；打開後也看 GitHub 上的預發佈版本。預設關閉。
  - **自動更新** — 偵測到新版本時在背景自動升級並重啟。預設關閉。
  - **更新檢查間隔** — 背景多久向 GitHub 確認一次，1–60 分鐘，預設 5 分鐘。按「檢查更新」與升級一律當場查，不受這一格影響。
- **備份健康** — 排程備份有沒有持續產生還原點：「備份正常」「備份異常」「無法判斷」。卡片列出最新排程備份、異常已持續多久、保鮮期與伺服器診斷。「無法判斷」不代表沒問題。
- **簽章金鑰** — 伺服器用來簽發登入憑證與分享連結的金鑰。卡片寫「目前有 N 把金鑰」，使用中的那把標「使用中」，其餘標「舊金鑰（仍有效）」。
  - **產生新金鑰** — 產生一把新金鑰並改用它簽發。已登入的人不會被登出，立即生效。
  - **移除** — 那把金鑰簽過的登入憑證與分享連結（檔案的、比較的）當場全部失效，不會通知任何人，也無法復原。還沒換到新金鑰的機器會在移除後斷線；離線的機器要等它上線才會換。移除前請確認每台機器都已換到新金鑰。

金鑰的安全面見 [保護你的工作室](security.md)；從頭安裝與移除見 [安裝、升級與移除](install.md)。

## 全域情境

送給成員的文件都在這一頁，你可以編輯，存檔後成員下次讀到的就是新內容。文件分三組：

| 組 | 文件 | 成員什麼時候讀到 | 字數上限 |
| --- | --- | --- | --- |
| 上線（BOOT） | 系統互動 | 每位成員開機時 | 60000 |
| 上線（BOOT） | 使用者自訂 | 每位成員開機時 | 無 |
| 上線（BOOT） | 啟動步驟（Claude Code） | Claude Code 成員開機時照著做 | 15000 |
| 上線（BOOT） | 啟動步驟（Codex CLI） | Codex 成員開機時照著做 | 15000 |
| 下線（STOP） | 停止 | 成員被停止時 | 15000 |
| 下線（STOP） | 加速停止 | 成員被要求提前收工時，附截止時間 | 15000 |
| 任務事件（TASK） | 任務結案 | 任務被判定結束時 | 15000 |
| 任務事件（TASK） | 任務轉派 · 給前任 | 手上的任務被轉給別人時 | 15000 |
| 任務事件（TASK） | 任務轉派 · 給接手人 | 接手任務時（有沒有前任都用這份） | 15000 |
| 任務事件（TASK） | 擋著你手上任務的票解開了 | 依賴的任務放行時 | 15000 |
| 任務事件（TASK） | 你手上的任務可以結案了 | 任務每次進到可結案時 | 15000 |

- 「啟動步驟」在清單上是一列，點進去用「一般／Codex」切換兩份文件。
- 字數上限是出廠值，參數調整頁上沒有這幾格。有上限的文件，卡片標題列會顯示「目前字數 / 上限」。
- 有幾份文件的開頭是程式產生的唯讀區（例如成員名字、截止時間），標成「唯讀區（程式產生，改不動）」；你只能改唯讀區之後的段落。儲存會用編輯框的內容取代可編輯的部分。
- 有預設內容的文件，卡片標「與預設內容同步」或「已修改」。
- 存檔前會先確認。啟動步驟要特別小心：寫壞會讓之後開機的成員無法上線，而且不會有任何錯誤訊息。出事時到版本紀錄打開「預設內容」，按「同步預設內容」。

**使用者自訂**是最值得你花時間寫的一份。把你是誰、專案在做什麼、預算多少、哪些 repo 絕對不能動寫進去，每位成員每次開機都讀得到，你就不必每次重講。

## 角色誌

每個角色一頁，頁上有兩份文件：

- **角色定義** — 這個角色負責什麼、遵守哪些規矩。改了之後，這個角色的成員下次開機讀到新內容。
- **判準(Insight)** — 這個角色反覆用到的取捨與界線，通常由該角色的成員自己寫進來。所有成員都讀得到任何角色的判準；只有該角色自己的成員與管理員能寫。

角色清單上可以「新增角色定義」「重新命名角色」「刪除」。刪除角色時，該角色的正職成員會標成已離開，聊天紀錄保留為唯讀；角色定義與判準會永久刪除。有成員在線上時不能刪除。新增角色就是多請一位正職，做法見 [增加成員與發外包](members.md)。

## 任務手冊

每一類任務的作業手冊，分「內建」與「自訂」兩組。手冊頁有「任務定義」（顯示名稱、這是什麼任務、需要哪些資訊、該怎麼做）與「負責成員」（指定成員或外包；外包另設模型、投入程度、機器、雇用數量）。手冊的負責成員只有你或你的特助能設。

怎麼寫手冊、怎麼挑識別鍵與關卡，見 [讓 AI 照 SOP 做重複的事](sop.md)。

## 版本紀錄

全域情境的每一份文件、角色定義、判準(Insight)、任務手冊的 SOP 都有版本紀錄：

- 系統互動、啟動步驟、停止、加速停止與 5 份任務事件文件各保留最近 10 次修改；其他文件（使用者自訂、角色定義、判準、SOP 等）保留最近 3 次。以存檔次數計，不是以時間計，連續小修幾次就會把較舊的版本沖掉。
- 入口在編輯模式：按「編輯」後，按鈕列多一顆「版本紀錄」。
- 清單每一列寫被取代的時間與修改者。點一列打開那一版，可在「版本內容」與「與目前的差異」之間切換；差異比的是伺服器上存著的內容，不含編輯框裡還沒存的修改。
- 「還原這個版本」會覆蓋目前內容，而目前內容會存成新的一版，所以還原後還能再退回來。
- 有預設內容的文件，清單最後一列是「預設內容」，打開後可以看內容、看差異，再按「同步預設內容」。「使用者自訂」的預設內容是空白的，同步等於清空。內建任務手冊同步預設內容時，整本手冊（名稱、用途、識別鍵、SOP 與負責成員）都會回到預設設定。
- 任務手冊只有 SOP 留版本；用途與識別鍵的修改不留版本。
- 整份刪除角色或自訂手冊時，版本紀錄一起刪除，無法還原。
- 超過目前字數上限、而且沒有比目前內容短的版本，在清單上標「無法還原」並寫出原因。

畫面由上到下的每一格：

| 參數 | 用途 | 範圍 | 預設 |

| 登入有效期 | 你登入後多久需要重新輸入密碼 | 12 小時／24 小時／7 天／30 天 | 24 小時 |
| 成員登入有效期 | 新啟動的成員與外包多久需要重新取得登入憑證 | 12 小時／24 小時／7 天／30 天 | 7 天 |

**換手門檻**：成員的記憶用到門檻時，會先收尾、留下交接，再由伺服器重新開一個接著做。門檻調低，換手更頻繁；調高，每一輪跑得更久。Claude 成員只看百分比那兩格，Codex 成員只看記憶壓縮次數那兩格，調錯那一組不會有任何提示。想手動換手一次，在成員詳情按「重新聚焦」。

**字數上限**：調低任何一格字數上限，都不會截斷或刪除已經存好的內容。

- 角色定義、Insight、SOP：上限只在寫入時檢查。已經超過上限的文件，只要新版比舊版短，仍然存得進去。成員讀這三種文件時會一併看到目前字數與上限。
- 步驟備註：已經超過新上限的備註照樣完整讀得到，但要先寫短到上限以下才能再修改。這一格只管步驟備註；聊天訊息與轉派的交接備註有各自固定的上限，不跟著這一格變。
- 成員傳承與任務傳承：超過上限時，放不下的整筆條目成員讀不到，也不會有錯誤訊息；傳承分頁上的上限線標出從哪一筆開始讀不到。
- 傳承標題與內容：超過上限的寫入整筆被拒絕，已經存好的條目不受影響。

**喚醒聊天字數預算**：調低只會讓成員下次喚醒時帶回的訊息變少，不會刪掉任何聊天紀錄；沒帶回的部分成員可以自己再讀。調高讓成員醒來時多讀一些對話，代價是每次喚醒都多花那些字。

**備份保留份數**是唯一一格調低會刪掉東西的參數：

- 算的是份數，不是天數。能回溯多久取決於那段時間實際備份了幾次。
- 日常備份與升級前備份各自保留這個份數，所以磁碟上最多會有兩倍的檔案。
- 超過的份數在下一次備份時永久刪除，救不回來。

**建議回覆**：三份清單各自獨立。點一句只會把句子填進輸入框，不會替你送出；輸入框已經有字時，句子接在後面另起一行。清單可以留空，留空時對應的輸入框下方不顯示建議。超過字數上限的句子會被拒絕存檔，不會被自動截短。

## 風險與成本的界線

成員的判斷有一條最上層的原則：風險底線由你定。還在你能接受的範圍內，成員就自己做；一旦可能超支、造成無法挽回的損害（弄壞線上服務、刪資料、洩漏機密），或要選一個難回頭的大方向，成員應該停下來開請示卡問你。

要讓這條原則有用，你要做三件事：

- **把邊界寫清楚**：哪些 repo 能碰、哪些絕對不能動、什麼事要先問、預算大概多少。寫進「設定 › 全域情境 › 使用者自訂」，每位成員每次開機都讀得到。
- **把要付代價的決定設成關卡**：在任務手冊裡把這類步驟設成關卡，成員做到那一步就會停下來等你，做法見 [讓 AI 照 SOP 做重複的事](sop.md)。
- **知道成員的權限有多大**：成員的 runtime 以跳過權限確認的方式執行（Claude Code 用 `--dangerously-skip-permissions`，Codex 用 `approvalPolicy: never` 加 `sandbox: danger-full-access`），因為背景執行時沒有人在旁邊按確認。所以成員在你的機器上有很大的行動自由，限制它的是它讀到的守則與「該問就停下來開卡」的機制，不是系統的權限控管。請在接受這一點之後再使用。

成員用的是你自己的 Claude 與 Codex 帳號，費用也算在你的帳號上。「監控」分頁列出每個帳號的 5 小時窗與 7 天窗用量、是否過熱、估計花費，以及每個 AI 會話用哪台機器、哪個模型、花了多少，值得定期看一眼。
