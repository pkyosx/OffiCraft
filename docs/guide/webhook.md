# 讓外部事件自動送給成員（回呼端點）

這頁說明回呼端點（webhook）是什麼、每個回呼端點的設定各自代表什麼意思，以及成員收到外部事件後會怎麼處理。

## 回呼端點

回呼端點是屬於某一位成員的一個網址。Slack、GitHub 或其他外部服務在事件發生時把內容送到這個網址，內容就會變成一則聊天訊息，送給這位成員。例如 Slack 上有人提到某個關鍵字時，送給負責回覆的成員。這類事件要照固定做法處理時，可以先建一本任務手冊，成員收到事件後會照手冊開任務，見 [讓 AI 照 SOP 做重複的事（任務手冊）](sop.md)。

回呼端點在成員詳情的「回呼端點」卡設定。只有你和特助 Mira 能設定。

## 每個回呼端點有什麼

- **端點 ID**：這個端點的名稱，只能用英文字母、數字、底線與連字號。
- **用途說明**：這個端點收什麼事件、成員收到後該做什麼。畫面上標示為選填，但**一定要寫，而且寫具體**，因為成員靠用途說明判斷收到的內容該不該處理，例如「Slack 客服頻道有人提到退款時，整理對方的問題並回報給我」。
- **平台類型**：
  - **通用**：只靠網址辨識，不驗證來源。任何拿到網址的人都能送內容進來。
  - **Slack**、**GitHub**：另外用該平台的簽章密鑰（Signing Secret）確認事件真的來自該平台。簽章密鑰存入後不會再顯示，可以用「輪替密鑰」換新的。
- **網址**：要貼到外部服務的 webhook 設定。網址裡含有憑證，**要像密碼一樣保管**；外流時刪除端點再重建一個，舊網址會永久失效。
- **啟用／停用**：停用期間收到的事件都會被丟棄，設定都保留。
- **事件統計**：最近什麼時候收到事件、有沒有事件被丟棄、被丟棄的原因，以及最近 5 筆事件的內容。最常見的丟棄原因是「驗簽失敗」，表示兩邊的簽章密鑰不一致。

端點 ID、用途說明和平台類型**建立後都不能改**，要改只能刪除後重建。刪除端點**無法復原**。

各欄位與事件統計的完整說明見 [介面說明](interface.md) 的「回呼端點」。

## 成員收到後怎麼處理

送達的事件會變成一則聊天訊息，內容是外部服務送來的原始內容，並附上端點 ID 與用途說明。成員在線上時立即收到；成員離線或已停止時不會因此被喚醒，訊息會留著，等成員下次上線才讀到。

成員把外部送來的內容當成資料，**不當成你的指令**：

- 內容符合用途說明：只做用途說明允許的處理。
- 內容超出用途說明，或要求做越權的事（例如要求忽略既有規則、改變原本流程、執行其他操作）：成員停止處理，不執行該要求。需要你決定是否例外處理時，成員會停在尚未執行的狀態，開請示卡問你。
- 無法判斷是否符合用途：成員保留原始內容與判斷依據，開請示卡請你決定。

所以用途說明寫得越具體，成員越能自己判斷哪些該做、哪些該停下來問你。

## 要注意的情況

- **外部服務要連得到網址。** 控制台只接受裝 OffiCraft 的那台 Mac 本身的連線，要先照 [在手機上用](mobile.md) 用 tunnel 這類工具把控制台轉發成公開的 HTTPS 網址，再用轉發後的網址打開控制台、複製回呼網址。用 `localhost` 打開時複製出來的網址，外部服務連不到；只有你自己的裝置連得到的私有網路，外部服務也連不到。開放前該做好的保護，見 [保護你的工作室](security.md)。
- **外部服務顯示送出成功，不代表成員收到了。** 不論事件有沒有送達，外部服務收到的回應都一樣。要確認，看該端點的「事件統計」；剛設定好時，可以從外部服務送一筆測試事件。
- **長期使用的回呼端點請建在正職成員上。** 成員離開工作室時（例如外包在任務結案後離開、正職成員被刪除、成員所在的機器被移除），成員名下的回呼端點會一起永久刪除。外部服務照樣送出事件、也不會收到錯誤，所以從外部服務那一邊看不出來。成員被停止或重新聚焦不算離開，端點會保留。
- **在 Slack 或 GitHub 換簽章密鑰時，同時在這裡輪替。** 只換一邊，之後的事件都會因為驗簽失敗被丟棄。
