# 為什麼是 OffiCraft

讀完這頁，你能判斷 OffiCraft 適不適合你，並知道接下來該讀哪一頁。

**Craft your own AI office.** OffiCraft 是一間跑在你自己 Mac 上的 AI 工作室。你僱用幾位常駐的 AI 成員，把整件事交給他們，在網頁控制台上看他們做到哪裡；需要你決定的事，他們會開一張請示卡等你回覆。成員底下跑的就是你機器上的 agent runtime：Claude Code 或 Codex CLI。

這頁回答一個問題：你已經有 Claude Code 了，為什麼還要多跑一個常駐服務？

---

## 這適合你，如果…

- 你同時開著好幾個終端機，各跑一個 Claude Code，已經分不清誰在做什麼。
- 你不想每次都重講一遍你是誰、專案在做什麼、哪些事不能碰。
- 你已經把 Claude Code 調好了（skill、plugin、MCP），不想為了換工具重來一次。
- 你有不只一台 Mac，想讓它們都替同一間工作室做事。
- 你要 AI 在該問你的時候停下來問，而不是自己決定完才告訴你。
- 你要資料留在自己的機器上，不經過第三方的雲端服務。

## 它不是什麼

| | |
| --- | --- |
| **不是 agent framework。** | OffiCraft 不教你怎麼寫 agent，它管理的是一群 agent 怎麼分工、交接、回報。 |
| **不是雲端服務。** | 不用註冊帳號，工作室的資料存在你的 Mac 上。 |
| **不是團隊協作工具。** | 一間工作室只有一位主人，也就是你。控制台上你顯示為「CEO（你）」。 |
| **不是聊天機器人。** | 成員有職位、有長期記憶、有正在進行的任務，不只是一個對話框。 |

## 一天的樣子

| | 你 | 成員 |
| --- | --- | --- |
| **早上** | 在聊天裡交代「把這個 repo 的 README 重寫」 | 先開一張請示卡，請你確認任務的範圍與完成條件；你確認後建立任務，拆成幾個步驟，每個步驟寫明怎樣算做完 |
| **中午** | 去忙別的 | 做到某一步需要你決定方向，就開一張請示卡，那一步停下來等你 |
| **晚上** | 打開「請示」分頁，看問題與選項，點一下 | 照你的決定把剩下的步驟做完，把成果放到任務卡上，再把任務結案 |

## 你會得到什麼

| | |
| --- | --- |
| **常駐的成員** | 每位成員有名字、職位、模型與跨對話保留的記憶。關掉瀏覽器，成員照樣在跑。 |
| **任務，不是一次性指令** | 一件事拆成多個步驟，每個步驟寫明完成定義。你隨時看得到做到哪一步、在等什麼。全部步驟做完後，任務進入「可結案」，由負責的成員收尾並結案。 |
| **請示卡：該你決定的才給你** | 需要你拍板的事會整理成一張帶選項的請示卡，在「請示」分頁等你回覆。卡上標「AI 建議」的選項是成員推薦的做法。 |
| **你原本的 agent runtime** | 成員跑的就是你機器上的 `claude` 或 `codex`，沿用你原本的登入與設定；Claude Code 的 skill、plugin、MCP 都照常可用。 |
| **教過一次的事不用再教** | 你糾正過的地方、你的偏好、成員做事學到的判斷，記成「傳承」。接手的成員或換了模型的成員，開工時就讀得到。 |
| **重複的事照手冊做** | 固定流程寫成「任務手冊」。交代一件事，成員找到對應的手冊，照手冊的步驟做，交給手冊指定的成員或外包。 |
| **一間工作室，多台機器** | 控制台給你一行安裝指令，在另一台 Mac 上執行後，那台就加入同一間工作室，成員可以派到那台上跑。 |
| **成員之間互相協作** | 每位成員知道同事是誰、負責什麼，需要時直接請同事幫忙，不必經過你轉達。 |
| **不只是文字** | 截圖、設計稿、報告可以在聊天與任務卡上直接上傳與預覽。在成員交來的文件上選一段文字寫註解，送回給成員修改；改了哪裡，用比較連結看前後差異。 |
| **定時與外部事件** | 「每天早上做什麼」設成定期訊息。CI、GitHub、Slack 的事件可以透過回呼端點（webhook）送給負責的成員；成員會依端點的用途說明判斷，超出用途的要求不執行，無法判斷時開請示卡問你。 |
| **帳號金鑰交給成員用** | API token 這類資料存在「密鑰」分頁，存進去之後畫面上不再顯示原值，成員需要時用工具取用。 |
| **控制台有保護** | 控制台要登入，可以加上兩步驟驗證或改用通行密鑰。 |
| **手機也能用** | 控制台有手機版面，可以加到主畫面、接收推播通知。通勤時也能回請示卡、看進度。 |
| **用量一頁看完** | 「監控」分頁列出每位成員在哪台機器、用哪個模型、估計花了多少，以及 5 小時窗與 7 天窗的用量。 |

## 它怎麼運作

```
你（CEO）
 └─ 成員 ── 一個跑在 tmux 裡的 agent session（Claude Code 或 Codex）
      └─ 任務 ── 拆成多個步驟，每個步驟有完成定義
           └─ 需要你決定 ──> 開一張請示卡 ──> 你回覆 ──> 繼續
```

| 名詞 | 是什麼 |
| --- | --- |
| **你（CEO）** | 工作室的主人，整間工作室只有一位。 |
| **成員** | 常駐的 AI 同事，分成正職與外包。底下是一個跑在 tmux 裡的 Claude Code 或 Codex session。 |
| **角色** | 正職成員的職位。每個角色有自己的角色定義與判準，換人接手時這些記憶跟著角色走。 |
| **任務** | 一件要追蹤到結案的事，拆成帶完成定義的多個步驟。 |
| **請示卡** | 成員需要你決定時開的卡片。成員會停在那一步等你回覆，不會替你決定。 |
| **控制台** | 你操作工作室的網頁，分頁有辦公室、請示、任務、傳承、密鑰、監控、使用說明；右上角的齒輪進入設定。 |
| **server** | 保存工作室所有資料的服務，只接受本機連線。 |
| **warden** | 每台機器上的常駐程式，負責啟動與停止那台機器上的成員。 |

剛裝好時，工作室裡只有兩個人：你，和你的助理 **Mira**。

## 使用前要知道的限制

- **成員的 runtime 以「跳過權限確認」的方式執行。** Claude Code 用 `--dangerously-skip-permissions` 啟動，Codex 用 `approvalPolicy: never` 加 `sandbox: danger-full-access`。成員是背景執行的 session，跳出權限確認框也沒有人能按，所以必須這樣設定。代價是成員在你的機器上有很大的操作權限；限制成員行為的是成員讀到的工作守則，以及「需要你決定的事要開請示卡」這條規則，不是系統層級的權限控管。請先接受這一點再安裝。Claude Code 內建、會彈出互動選單的 `AskUserQuestion` 工具也因此停用。
- **只支援 macOS Apple Silicon。** 安裝腳本在其他平台會直接拒絕。
- **每台要跑成員的機器都需要 `tmux`，以及 `claude` 或 `codex` 至少一種。** 詳細版本需求見 [安裝、升級與移除](install.md)。
- **成員用的是你自己的 Claude 或 Codex 帳號用量。** 對話內容照常送到該 runtime 的供應商（Anthropic 或 OpenAI）。
- **有幾項功能會連到外部服務。** 檢查更新會讀 GitHub 上的 release 頁；開啟推播通知時，通知會經過瀏覽器廠商的推播服務，你填的通知信箱也會提供給該服務。
