# 保護你的工作室

讀完這頁，你能管理誰進得了控制台、在開放手機或外部連線之前做好準備，並知道哪些金鑰與檔案需要保管好。

控制台背後就是你的整間工作室：成員在你的機器上有很大的操作權限，密鑰分頁裡存著你交給成員的帳號金鑰。所以登入控制台的方式要先設好，再考慮從外部連線。

---

## 登入密碼

第一次打開控制台時設定的密碼，就是登入控制台的密碼，至少 8 個字。密碼只以雜湊形式存在本機資料庫，不寫在任何設定檔裡。

**修改密碼**：點右上角頭像 › 帳號安全 › 修改密碼，輸入目前密碼與兩次新密碼，按「儲存」。

- 改密碼後，其他裝置與分頁上已登入的控制台都會被登出，需要用新密碼重新登入。你改密碼時正在操作的分頁維持登入。
- 改密碼不影響已註冊的通行密鑰，也不影響成員與機器的連線。

**登入失敗的處理**：

- 每次登入失敗，server 都會等約 3 秒才回應；密碼正確時立即放行。同一時間最多處理 4 個登入請求，額滿時畫面會顯示「目前同時處理的登入太多，請於 N 秒後再試。」，等幾秒再試即可。登入失敗不累計次數，不會把帳號鎖住。
- 開啟兩步驟驗證後，如果有人密碼輸入正確、但驗證碼錯誤，代表密碼可能已經外流。server 會傳訊息給助理 Mira，請她提醒你改密碼；同一段時間內只會傳一則，並附上累計次數。

## 兩步驟驗證

開啟後，每次用密碼登入都要再輸入驗證器 App（例如 Google Authenticator、1Password、iPhone 內建的密碼 App）顯示的 6 位數驗證碼。控制台要從外部連線時，建議開啟。

兩步驟驗證預設沒有開放，要先開放再設定：

1. 點右上角頭像 › 帳號安全 › 兩步驟驗證。
2. 打開「為這台伺服器開放兩步驟驗證」。這一步只是讓設定選項出現，不會替你開啟。
3. 按「設定兩步驟驗證」。畫面會顯示 QR code、一組「設定金鑰」，以及「用驗證器 App 開啟」連結。用驗證器 App 掃 QR code，或在手機上點連結，或手動輸入設定金鑰，三種方式擇一。
4. 輸入密碼與驗證器顯示的驗證碼，按「確認並開啟」。

QR code 在你的瀏覽器裡產生，設定金鑰不會送到任何第三方。

**關閉兩步驟驗證**：在同一個地方按「關閉兩步驟驗證」，需要輸入密碼與目前的驗證碼。

關掉「為這台伺服器開放兩步驟驗證」不等於關閉兩步驟驗證：它只會收起設定入口，已經開啟的兩步驟驗證在登入時仍然要輸入驗證碼。

**驗證器遺失**：在裝 server 的那台機器上執行：

```bash
~/.officraft/bin/ocserverd mfa-disable
launchctl kickstart -k gui/$(id -u)/com.officraft.serve
```

第一行清除兩步驟驗證，第二行重啟 server。一定要重啟，否則 server 仍會要求驗證碼。能在那台機器上執行指令，就證明你是工作室的主人。

## 通行密鑰

通行密鑰讓你用 Face ID、Touch ID、指紋、裝置密碼或實體安全金鑰登入，不用輸入密碼，也不用輸入兩步驟驗證的驗證碼。密碼登入的方式照常可用。

**新增**：

1. 點右上角頭像 › 帳號安全 › 通行密鑰。
2. 在「新增通行密鑰」輸入目前的密碼，以及一個認得出來的裝置名稱（例如「Eva 的 MacBook」）。
3. 按「新增通行密鑰」，照瀏覽器跳出的系統對話框完成。

新增時要再輸入一次密碼，是為了讓拿到你登入狀態的其他人無法偷偷加入自己的通行密鑰。之後登入頁會出現「用通行密鑰登入」。

瀏覽器版本需要 Chrome／Edge 129、Firefox 119、Safari 18.4 以上。版本太舊時，畫面會提示「此瀏覽器版本不支援通行密鑰，請更新瀏覽器」。

**每一把通行密鑰只能在註冊時的網址使用**：

- 用不同網址打開控制台（例如 tunnel 的 HTTPS 網址與 `http://localhost:7755`）時，要在每個網址各自註冊。在電腦上用 `localhost` 註冊的通行密鑰，手機上用 tunnel 網址登入時無法使用。
- 用 `http://127.0.0.1:7755` 這類 IP 位址打開時，不能使用通行密鑰。畫面會提示改用 `localhost` 的網址開啟，兩個網址打開的是同一間工作室。
- 清單上每一把通行密鑰都會顯示「綁定網址」，不是目前網址的會標示「此網址無法使用」。看到不認得的綁定網址，直接刪除。

**清單上的標示**：

- 「可能被複製，建議刪除」：有人用這把通行密鑰登入時，回報的使用次數比上一次還小，看起來像被複製過，那次登入已被拒絕。請刪除它，再用原本的裝置重新註冊。
- 「最後使用」：這把通行密鑰最後一次登入的時間，從沒用過時顯示「尚未使用」。

**遺失其中一台裝置**：用密碼（或其他裝置的通行密鑰）登入，在通行密鑰清單把那一把刪除。刪除後立即無法再用它登入；已經用它登入的分頁會維持登入，直到登入有效期到期或你改密碼。

**全部遺失，或想一次清空**：在裝 server 的那台機器上執行 `~/.officraft/bin/ocserverd passkey-reset`。所有通行密鑰立即刪除，不需要重啟 server，之後用密碼登入。

## 登入有效期

登入後多久需要重新登入，在 **設定 › 參數調整 › 登入有效期** 調整，可選 12 小時、24 小時、7 天、30 天，預設 24 小時。新的設定從下一次登入開始生效。

控制台會從外部連線，或會在別人也碰得到的裝置上登入時，建議選短一點。

## 一次性登入連結

一次性登入連結讓你在裝 server 的那台機器上，產生一條可以直接登入控制台的連結，適合手邊的裝置不方便輸入密碼時使用。一次性登入連結預設關閉。

```bash
~/.officraft/bin/ocserverd login-link enable                                 # 開啟功能
~/.officraft/bin/ocserverd login-link --base-url https://你的控制台網址         # 產生一條連結
~/.officraft/bin/ocserverd login-link disable                                # 關閉功能，所有連結立即失效
```

- 每條連結 10 分鐘內有效，只能登入一次。產生新連結時，前一條連結立即失效。
- 用連結登入時不需要兩步驟驗證的驗證碼，因為能在那台機器上執行指令的人，本來就能關閉兩步驟驗證。拿到連結的人就能登入，請只在自己的裝置上打開，不要轉傳。
- 連結失效時，畫面會顯示「登入連結已失效（已使用、超過 10 分鐘或站台未開啟），請用密碼登入或請人重新產生。」
- 不加 `--base-url` 時，印出的連結只有 `/?login=…` 這一段，要自己接在控制台網址後面。
- 用完之後，建議執行 `login-link disable` 把功能關閉。

## 開放外部連線之前

server 預設只接受本機連線（`127.0.0.1`），裝好之後不會對外開放。要從手機或其他電腦使用控制台，需要自己開一條連線通道：

| 做法 | 適合 |
| --- | --- |
| **tunnel**（例如 cloudflared） | 想從任何地方連線。tunnel 會給你一個公開的 HTTPS 網址，任何知道網址的人都能打開登入頁。 |
| **VPN 或 Tailscale 這類私有網路** | 只在自己的裝置之間連線，不開公開網址。 |

開通道之前，先完成這幾件事：

1. 把登入密碼換成夠長、沒在別處用過的密碼。
2. 開啟兩步驟驗證，或改用通行密鑰登入。
3. 視需要把登入有效期調短。

不要把 server 直接開在沒有 HTTPS 的公開埠上。手機連線與加到主畫面的步驟見 [在手機上用](mobile.md)。

開了公開網址之後，回呼端點（webhook）的接收網址也會一起對外。接收網址不需要登入，靠網址裡的 token 與簽章密鑰辨認來源；簽章密鑰怎麼設定、怎麼輪替，在 [讓外部事件自動送給成員](webhook.md)。

## 回呼端點的簽章密鑰與用途說明

回呼端點讓外部服務（例如 Slack、GitHub）把事件送給成員。每個端點有一條帶 token 的接收網址，拿到這條網址的人就能送事件給成員，所以請只把它填在要串接的服務裡。

- **平台類型**選「通用（僅 URL token）」時，只靠網址裡的 token 辨認來源。
- 選「Slack」或「GitHub」時，必須填**簽章密鑰 Signing Secret**，也就是該平台提供的共享密鑰。server 會用它驗證每個請求的簽章，驗證失敗的請求會被丟棄，在「事件統計」裡記為「驗簽失敗」。
- 懷疑簽章密鑰外流時，先在 Slack 或 GitHub 換一組新的密鑰，再到端點按「輪替密鑰」貼上新值並「儲存密鑰」。
- 懷疑接收網址外流時，刪除該端點，再建一個新的。刪除後原本的 token 永久失效。
- **用途說明**是選填，但建議填寫。外部送來的內容一律被成員當成資料，不當成你的指示；成員會依用途說明判斷內容是否在範圍內，超出用途或要求越權的內容不執行，無法判斷時開請示卡問你。

建立端點、接 Slack 與 GitHub 的完整步驟見 [讓外部事件自動送給成員](webhook.md)。

## 密鑰與 vault.key

「密鑰」分頁裡的值，是用一把金鑰檔 `vault.key` 加密後存進資料庫。`vault.key` 和資料庫放在同一個資料夾（官方 release 安裝是 `~/.officraft/server/data/`），檔案權限只有你自己能讀。

- 資料庫備份（自動備份與 `ocserverd backup`）**不包含** `vault.key`。這是刻意的：單獨一份資料庫備份外流時，裡面的密鑰無法被解開。
- 請把 `vault.key` 另外保存在安全的地方，不要和資料庫備份放在一起。
- 還原資料庫時，要把同一把 `vault.key` 放回資料庫所在的資料夾。少了它，原本的密鑰無法讀取，也無法修改，只能在密鑰分頁刪除後重新建立。

新增、修改、刪除密鑰，以及成員怎麼取用，見 [把帳號金鑰交給成員用](secrets.md)。

## 簽章金鑰

簽章金鑰是 server 用來簽發登入憑證與分享連結的金鑰。控制台、成員、機器的登入憑證，以及「複製對外連結」與「複製分享連結」產生的連結，都用它簽章。在 **設定 › 系統更新與備份** 最下方的「簽章金鑰」卡管理。

卡上會列出目前有幾把金鑰：標「使用中」的那把負責簽發新的憑證；標「舊金鑰（仍有效）」的不再簽發，但用它簽過的憑證與連結仍然有效。

**產生新金鑰**：按「產生新金鑰」，新金鑰立即接手簽章。已登入的人不會被登出，不需要重啟。之後每台在線上的機器會自動換成新金鑰簽的憑證；離線的機器要等它上線後才會換。

**移除**：按舊金鑰旁的「移除」。移除沒有復原，而且立即生效：

- 用這把金鑰簽的登入憑證全部失效，用到它的控制台分頁要重新登入。
- 用這把金鑰產生的分享連結（檔案的、比較的）全部失效，持有連結的人不會收到通知。
- 還沒換到新金鑰的機器會立刻斷線。

所以移除之前，請確認每台機器都已經上線過、換到新金鑰。

懷疑登入狀態或分享連結外流時，先「產生新金鑰」，等所有機器都換好之後，再「移除」舊金鑰。

## 成員與機器的憑證有效期

成員和機器連到 server 也要用登入憑證，有效期在 **設定 › 參數調整** 調整：

| 參數 | 意思 | 範圍與預設 |
| --- | --- | --- |
| **成員登入有效期** | 新啟動的成員與外包，多久需要重新取得登入憑證。 | 12 小時、24 小時、7 天、30 天，預設 7 天。 |
| **機器憑證壽命** | 機器的登入憑證有效期。機器會在到期前自動換新；錯過換新的機器要重新安裝。 | 86400–34560000 秒（1–400 天），預設 30 天。 |

兩個參數調小都不影響已經發出的憑證，只影響之後新發出的。
