# 讓成員記住你教過的事

讀完這頁，你能把工作室的規矩、各角色的職責和成員從工作中學到的經驗存在 server 上，讓每一位成員開機時都讀得到，不必每次重講。

## 成員開機時會讀到哪些你寫過或認可過的內容

成員每次開機（包括換手後的新一手），server 會把下列內容組進它的開機文件：

| 內容 | 誰寫 | 開機時自動讀到 | 在哪裡管理 |
| --- | --- | --- | --- |
| **使用者自訂** | 你 | 每一位成員，正職與外包都有 | 設定 › 全域情境 › 使用者自訂 |
| **角色定義** | 你或特助 Mira | 該角色的正職成員 | 設定 › 角色誌 |
| **判準(Insight)** | 該角色的成員本人、特助或你 | 該角色的正職成員 | 設定 › 角色誌 › 角色內頁 |
| **成員傳承** | 成員自己 | 撰寫人本人 | 傳承分頁 |
| **「所有人」的傳承** | 成員寫入後由你或特助改掛 | 每一位成員 | 傳承分頁 |
| **任務傳承** | 成員自己 | 讀到這本任務手冊的成員 | 傳承分頁 |

角色定義與判準所有成員都查得到，但只會自動放進該角色的開機內容。

想看某位成員實際讀到的組合，打開它的成員詳情，「初始 PROMPT」區塊是依目前設定組出來的預覽，可能和它當初開機時收到的內容有出入。

## 全域情境的「使用者自訂」

「使用者自訂」是你最值得先寫的一份文件。它在 **設定 › 全域情境** 的「上線（BOOT）」那一組，預設是空白的，寫了之後每一位成員開機都會讀到。

建議一開始就寫進去的內容：

- 你是誰、這間工作室在做什麼專案。
- 哪些 repo、目錄或服務可以動，哪些絕對不能動。
- 什麼事一定要先開請示卡問你，例如寄信給外部、merge、動線上環境、花錢。
- 預算的大概範圍，以及你偏好的回報方式。

寫法：打開「使用者自訂」，按「編輯」，寫完儲存。儲存是整份取代。「使用者自訂」沒有字數上限，但它每次開機都會整份送給成員，寫得精簡比較好。

全域情境裡其他幾份文件（系統互動、啟動步驟、停止等）的用途與修改風險，見 [設定與參數](settings.md)。

## 角色誌：角色定義與判準

**設定 › 角色誌** 依角色列出每一個正職角色。每個角色有兩份文件：

- **角色定義**：這個職位負責什麼、遵守哪些規矩、哪些事不歸它管。你和特助可以編輯，改了之後該角色的成員下次開機讀到新版本。字數上限在 設定 › 參數調整 的「角色定義字數上限」（100–100000）。
- **判準(Insight)**：該角色在工作中反覆用到的取捨與界線，通常由該角色的成員自己寫入。畫面上的說明是：「所有成員都看得到這份判準；只有這個角色本人和管理員可以修改。」特助的判準有一份預設內容，其他角色的判準一開始是空的。字數上限在「Insight 字數上限」（100–100000）。

角色定義寫好的方向：寫「什麼事應該找該角色」與「該角色不能做什麼」，不要寫一次性的任務內容。一次性的事直接在聊天交代，反覆出現的工作流程寫成任務手冊，見 [讓 AI 照 SOP 做重複的事](sop.md)。

新增、改名與刪除角色等於增加或移除一位正職成員，做法見 [增加成員與發外包](members.md)。

## 傳承是什麼

傳承是成員在工作中確認過、之後還會用到的判斷原則。每一筆只記一個原則，由類型、標題和內容組成。成員在任務結案、被停止或判斷有值得留下的經驗時自己寫入；沒有值得留的就不寫。

傳承的類型標籤顯示在每一筆的最前面：

| 類型 | 什麼時候寫 |
| --- | --- |
| **指示衝突** | 成員實際做過後發現 SOP、系統文件或操作指示和正確做法不一致，照原指示做會出錯。原指示修正後，這筆應設為失效。 |
| **指示補充** | 原指示沒有錯，但缺少會影響結果的條件、例外或步驟。原指示補齊後，這筆應設為失效。 |
| **Owner 決策** | 你的判斷和成員原本預期不同，成員確認了背後的考量，而該考量之後的類似情況也適用。 |
| **Owner 偏好** | 你明確表達、預期長期適用的偏好，例如回報方式、交付格式。單次要求不算。 |
| **其他** | 不屬於以上四類的條目。早期沒有標類型的傳承也歸在這一類。 |

一次性的任務資訊、某張票或某個客戶的細節，以及可以從程式碼或文件重新查到的內容，成員不會寫成傳承。如果經驗反映的是「SOP 本身應該改」，成員會開請示卡請你決定是否修改 SOP，而不是用傳承代替。

傳承寫入後內容不能修改。內容過時時，把它設為失效，請成員重寫一筆。控制台上沒有讓你直接新增傳承的按鈕；想讓某件事被記住，在聊天裡告訴成員，請它寫成傳承。

## 傳承的適用範圍

每一筆傳承掛在一個適用範圍下，範圍決定誰會讀到它：

- **成員傳承**：掛在撰寫人自己名下，只有撰寫人開機時讀到。成員寫入時沒有指定任務，或指定的任務沒有任務類型，就會掛在這裡。
- **任務傳承**：掛在某一本任務手冊下。成員寫入時指定了一張有任務類型的任務，就會掛在該手冊；之後任何成員讀這本手冊時會一併讀到。
- **所有人**：每一位成員開機都會讀到，和成員自己的成員傳承共用同一個字數上限。

要改範圍，在傳承分頁點該筆的範圍標籤，打開「適用範圍」選單。選項有「任務：手冊名稱」、「建立者：撰寫人名字」和「所有人」，其中標「預設」的是寫入時的原始範圍，標「目前」的是現在的範圍。來源任務沒有類型的條目沒有「任務」選項；撰寫人已不在名冊上的條目沒有「建立者」選項。改範圍只有你和特助能做，改了之後在成員下次開機或下次讀手冊時生效。

某位成員寫了一筆對大家都適用的原則（例如一筆 Owner 偏好），把它改成「所有人」，其他成員就不必各自再學一次。

## 在傳承分頁查看與篩選

上方導覽列的「傳承」分頁列出所有傳承，依狀態分成「置頂」「生效中」「已失效」三群，每一群內依生效期由新到舊排列。點一筆可以展開看完整內容、撰寫人、生效期和失效理由。

篩選列可以多選組合：

- **所有撰寫人**：誰寫的。
- **所有成員傳承**：掛在哪位成員名下，選項包含「所有人」。
- **所有任務傳承**：掛在哪本任務手冊下。
- **所有類型**：指示衝突、指示補充、Owner 決策、Owner 偏好、其他。
- **所有狀態**：置頂、生效中、已失效。

按「清除篩選」回到完整清單。點條目上的編號可以複製條目編號。任務傳承的「適用範圍」選單最下面有「開啟任務手冊」，可以直接打開該手冊。

## 上限線：成員讀得到哪幾筆

成員開機時讀傳承有字數上限，在 設定 › 參數調整 調整：

- **成員傳承字數上限**：每位成員開機時最多讀多少字（「所有人」的傳承加上它自己的成員傳承一起算），預設 10000 字。
- **任務傳承字數上限**：讀一本任務手冊時最多附帶多少字的任務傳承，預設 10000 字。
- **傳承標題字數上限**、**傳承內容字數上限**：單一筆的上限，預設 80 字與 500 字，超過的寫入會被拒絕。

server 依「置頂優先，其餘依生效期由新到舊」的順序一筆一筆放進去，放到第一筆放不下就停止，之後較舊的條目都不會被讀到，也不會有錯誤訊息。

篩選到單一範圍時（例如只選某一位成員、只選某一本手冊，或只選「所有人」），清單中間會出現一條上限線，例如「任務傳承 · 審查 PR 上限 10000 字，以下的傳承成員讀不到」。上限線以下的條目仍保存在 server，只是成員讀不到。

上限線以下有重要條目時，可以：

- 把過時的條目設為失效，騰出空間。
- 對重要的條目按「提到最新」或設為置頂。
- 調高對應的字數上限。

## 變更狀態與提到最新

每一筆傳承有三種狀態，點狀態徽章打開「變更狀態」選單切換：

- **生效中**：一般狀態，依生效期排序。
- **置頂**：排在同一範圍的最前面，優先放進字數上限內。只有你和特助能置頂或取消置頂。
- **已失效**：成員不再讀到。成員把條目設為失效時會附上理由，條目上顯示為「失效理由」。已失效的條目可以再設回生效。

「提到最新」把一筆的生效期改成現在，讓它排回生效中的最前面，原本的建立時間不變。成員也能對自己寫的條目做失效、生效與提到最新；你和特助可以對任何一筆操作。

## 傳訊息給撰寫人

對某一筆傳承有疑問或想請撰寫人改寫時，在條目的撰寫人那一列按「傳訊息給撰寫人」，直接在條目底下輸入。送出的訊息會以條目編號開頭（輸入框下方會註明「會以 編號 開頭送出」），撰寫人在聊天裡收到後就知道你在說哪一筆。訊息沒送出時，打的字會保留，可以再送一次。

## 版本紀錄：改壞了可以還原

使用者自訂、角色定義、判準和任務手冊的 SOP，每次存檔時 server 會把被取代的舊版本留下來，保留最近 3 次修改。

查看與還原：

1. 打開文件，按「編輯」。
2. 在編輯列按「版本紀錄」，清單列出每一版被取代的時間和修改者。
3. 點一版打開，可以切換「版本內容」和「與目前的差異」。差異比對的是伺服器上目前存著的內容，編輯框裡尚未儲存的修改不算在內。
4. 按「還原這個版本」並確認。目前的內容會被覆蓋，但會另存成一版，所以還原之後仍然可以退回。

有預設內容的文件（使用者自訂、特助的角色定義與判準、內建任務手冊），清單最後有一列「預設內容」。打開後可以先看內容與差異，再按「同步預設內容」回到預設。「使用者自訂」的預設內容是空白的，同步等於清空。

注意事項：

- 保留數是以存檔次數計算，連續存幾次小修改就會把較舊的版本擠掉。重要的內容自己另外留一份。
- 版本紀錄只涵蓋編輯。整個刪除一個角色或一本任務手冊時，它的版本紀錄會一起刪除，無法還原。
- 角色定義、判準和 SOP 各有字數上限。超過目前上限、而且沒有比目前內容短的舊版本，清單上會標「無法還原」並寫出原因。
- 任務手冊只有 SOP 留版本，用途與識別鍵的修改不留版本紀錄。

## 讓成員一直很有用

- **先寫好使用者自訂**：把「你是誰、專案在做什麼、哪些事不能碰」寫進去，之後每一位成員開機都讀得到，不必在每次對話重講。
- **把反覆出現的工作整理成任務手冊**：SOP 是同一類工作的固定流程，任務傳承則是做這類工作累積下來的判斷原則，兩者搭配，下一位接手的成員開工前就讀得到前人的經驗。
- **定期看一次傳承分頁**：把過時的條目設為失效，把適用所有人的原則改成「所有人」，確認重要條目在上限線以上。
- **讓成員自己換手**：成員記憶快滿時會自動換手，新的一手仍讀得到使用者自訂、角色定義、判準與傳承。你也可以在成員詳情按「重新聚焦」主動讓它整理記憶。換手門檻在 設定 › 參數調整。
- **交出去的是一件事，不是一步一步的指令**：把整件事連同「怎樣算做完」一起交代，讓成員自己拆解、推進，需要你決定時再開請示卡。
