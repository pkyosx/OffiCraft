# 讓成員記住你教過的事（傳承）

讀完這頁，你能把工作室的規矩、各角色的職責和成員從工作中學到的經驗存起來，讓每一位成員開工時都讀得到，不必每次重講。

這頁有三部分：你寫給所有成員的「使用者自訂」、每個角色的「角色定義與判準」，以及成員自己寫下的「傳承」。只想了解傳承，直接看「傳承是什麼」那一節。

## 先寫「使用者自訂」

「使用者自訂」是你寫給所有成員的一份文件。寫好之後，每一位成員每次開機都會讀到。這是你最值得先寫的一份文件，一開始是空白的。

1. 按頂列的齒輪，進入 **設定 › 全域情境**。
2. 在「上線（BOOT）」那一組打開「使用者自訂」，按「編輯」。
3. 寫完後儲存。

建議寫進去的內容：

- 你是誰、這間工作室在做什麼專案。
- 哪些 repo、目錄或服務可以動，哪些絕對不能動。
- 什麼事一定要先開請示卡問你，例如寄信給外部、merge、動線上環境、花錢。
- 預算的大概範圍，以及你偏好的回報方式。

使用者自訂每次開機都會整份送給成員，**寫得精簡比較好**。

全域情境裡其他幾份文件的用途與修改風險，見 [設定與參數](settings.md) 的「全域情境」。

## 風險與成本的界線

成員判斷事情時，最上層的原則是：**風險底線由你定**。在你能接受的範圍內，成員自己做；可能超支、可能造成無法挽回的損害（弄壞線上服務、刪資料、洩漏機密），或要選一個難回頭的大方向時，成員應該停下來開請示卡問你。

要讓這條原則有用，你要做三件事：

- **把邊界寫清楚**：哪些 repo 能碰、哪些絕對不能動、什麼事要先問、預算大概多少，寫進「使用者自訂」。
- **把要付代價的決定設成關卡**：在任務手冊裡把這類步驟設成關卡，成員做到那一步就會停下來等你，做法見 [讓 AI 照 SOP 做重複的事（任務手冊）](sop.md)。
- **知道成員的權限有多大**：成員在背景工作，旁邊沒有人能按確認，所以 Claude Code 和 Codex 都設成跳過權限確認、直接執行。成員在你的電腦上能做的事很多；約束成員的是成員讀到的守則，以及「該問就停下來開卡」的做法，不是系統的權限控管。請接受這一點之後再使用。

成員用的是你自己的 Claude 與 Codex 帳號，費用也算在你的帳號上。用量與估計花費怎麼看，見 [交代工作與回覆請示卡](daily.md) 的「看用量與花費」。

## 角色誌：角色定義與判準

每個正職角色有兩份文件，在 **設定 › 角色誌**：

- **角色定義**：這個角色負責什麼、遵守哪些規矩、哪些事不歸這個角色管。你和特助 Mira 可以編輯。
- **判準(Insight)**：這個角色在工作中反覆用到的取捨與界線，通常由該角色的成員自己寫。

改了之後，該角色的成員下次開機就會讀到新版本。

角色定義的寫法：寫「什麼事應該找這個角色」和「這個角色不能做什麼」，不要寫一次性的任務內容。一次性的事直接在聊天交代；反覆出現的工作流程寫成任務手冊。

新增、改名與刪除角色，等於增加或移除一位正職成員，做法見 [增加成員與發外包](members.md)。

## 傳承是什麼

傳承是成員在工作中確認過、之後還會用到的判斷原則，每一筆只記一個原則。成員在任務結案、被停止，或判斷有值得留下的經驗時，會自己寫一筆；沒有值得留的就不寫。

想讓成員記住某件事，在聊天裡告訴成員，請成員寫成傳承。控制台上沒有讓你直接新增傳承的按鈕。

傳承寫進去之後**內容不能修改**。內容過時時，把那一筆設為失效，再請成員重寫一筆。

一次性的任務資訊、某張票或某個客戶的細節，以及可以從程式碼或文件重新查到的內容，成員不會寫成傳承。經驗反映的是「SOP 本身應該改」時，成員會開請示卡請你決定要不要改 SOP，不會用傳承代替。

## 誰會讀到哪一筆傳承

每一筆傳承有一個適用範圍：

- **成員傳承**：只有寫下這一筆的成員讀得到。
- **任務傳承**：掛在某一本任務手冊下，之後讀這本手冊的成員都讀得到。
- **所有人**：每一位成員開機都讀得到。

某位成員寫了一筆對大家都適用的原則（例如一筆你的偏好）時，可以把範圍改成「所有人」，其他成員就不必各自再學一次：在「傳承」分頁點那一筆的範圍標籤，在「適用範圍」選單選「所有人」。只有你和特助能改範圍。

正職與外包開機時各讀到哪些內容，見 [架構與運作原理](architecture.md) 的「成員開機時讀到什麼」。

## 整理傳承

上方導覽列的「傳承」分頁列出所有傳承，可以依撰寫人、範圍、類型和狀態篩選。點一筆可以展開看完整內容。

**成員讀得到的傳承有字數上限。** 超過上限時，較舊的條目成員就讀不到，而且不會有錯誤訊息。篩選到單一範圍時（例如只選一位成員、只選一本手冊，或只選「所有人」），清單中間會出現一條上限線，線以下的條目成員讀不到。

上限線以下有重要條目時，可以：

- 把過時的條目設為失效，騰出空間。
- 對重要的條目按「提到最新」，讓那一筆排回生效中的最前面；或把那一筆設為置頂。
- 到 **設定 › 參數調整** 調高對應的字數上限。

每一筆傳承有三種狀態，點狀態徽章切換：

- **生效中**：一般狀態。
- **置頂**：排在同一範圍的最前面，優先讀到。只有你和特助能置頂。
- **已失效**：成員不再讀到。可以再設回生效。

對某一筆傳承有疑問，或想請撰寫人改寫時，在那一筆按「傳訊息給撰寫人」，直接在條目底下輸入訊息。

想知道更多細節，例如每種類型標籤的意思、上限怎麼計算、範圍選單的每個選項，見 [介面說明](interface.md) 的「傳承」。

## 改壞了可以還原

使用者自訂、角色定義、判準和任務手冊的 SOP，每次存檔都會留下舊版本。改壞了可以比較差異並還原，見 [設定與參數](settings.md) 的「版本紀錄」。

## 讓成員一直很有用

- **先寫好使用者自訂**：把「你是誰、專案在做什麼、哪些事不能碰」寫進去，每一位成員開機都讀得到。
- **把反覆出現的工作整理成任務手冊**：SOP 是同一類工作的固定做法，任務傳承是做這類工作累積下來的判斷原則。兩者搭配，下一位接手的成員開工前就讀得到前人的經驗。
- **定期看一次傳承分頁**：把過時的條目設為失效，把大家都適用的原則改成「所有人」，確認重要條目在上限線以上。
- **記憶快滿時讓成員重新開始**：成員記憶快滿時會自動整理記憶、重新開始，使用者自訂、角色定義、判準與傳承都還讀得到。你也可以在成員詳情按「重新聚焦」，主動讓成員整理記憶。
- **交出去的是一件事，不是一步一步的指令**：把整件事連同「怎樣算做完」一起交代，讓成員自己拆解、推進，需要你決定時再開請示卡。
