# 成員與外包

一間工作室裡幹活的是**成員**。這份講清楚兩種成員——**正職**與**外包**——差在哪、怎麼多請一個、怎麼管他們的上線與下線。

想先弄懂名詞，開 [名詞表](glossary.md)；想知道「什麼時候該外包」這種用法建議，看 [建議用法](best-practices.md)。

> 開箱時整間工作室只有兩個人：**你（owner），和 Mira**（你的助理，正職）。下面說的「多請一個」都是從這裡長出來的。

---

## 正職 vs 外包：一眼分辨

| | 正職（Staff） | 外包（Outsource） |
| --- | --- | --- |
| **身分** | 有名字、有**角色**、跨對話不忘的記憶 | 匿名，用**代號**稱呼（如 `O-7`），沒有角色記憶 |
| **在多久** | 常駐——你關掉瀏覽器它還在 | 臨時——綁一張任務，做完（或被終止）就退場 |
| **怎麼幹活** | 主 session 當**協調者**，粗重的工作交給 sub-agent 或發外包 | **自己下場做粗重的工作**（開發、測試、研究都自己來） |
| **記憶去哪** | 留在**角色誌**上（換人不換記憶） | context 用完即棄 |
| **數量** | 你一個角色一個角色地加 | 靠一個**全域同時雇用上限**守住，滿額排隊 |

一句話：**正職是你養的同事，外包是你臨時發的一包活。** 需要長期深耕、要記住脈絡的事交正職；能獨立切出去、做完即結案的一次性活發外包。

辦公室側欄頂部就是這兩欄的分頁：**Staff（正職）** 與 **Outsource（外包）**，各自列出名單。

---

## 多請一位正職＝新增一個角色

正職成員的背後是一個**角色（role）**：角色定義「這個職位是誰、負責什麼、遵守哪些規矩」，成員 session 只是當下填這個位子的人。所以「請一位新正職」在 OffiCraft 裡，就是**新增一個角色定義**。

**兩條路都到同一個地方：**

- 辦公室側欄最下方點 **招攬新成員**（在 Staff 分頁時）——它直接帶你到角色誌的新增畫面。
- 或自己走 **設定 › 角色誌 › 新增角色定義**。

填一個角色名（例如 `repo-maintainer`、`researcher`）就建好了。角色一建立，這台工作室就多一個正職成員——但它是**離線出生**的，**不會有人自動去叫醒它**，要它上線得你自己按一次喚醒。（按下去會先開一份啟動設定，裡面的執行環境那一格**顯示**的是 `claude`，改得動；但這位新成員出生時其實是**還沒有人選過執行環境**，真正定案在它第一次上機那一刻——見下方「[上線與下線](#上線與下線)」。）

> **角色定義與判準都在 設定 › 角色誌 裡。** 每個角色一塊，你隨時改得動它的定義；它累積的判準（Insight）也列在那裡。**換人不換記憶**——同一個角色換了新的 session，讀寫的還是同一份角色記憶。（怎麼寫好角色定義、把「你是誰／哪些事不能碰」寫進去，見 [建議用法](best-practices.md)。）

### 刪掉一個角色

在 **設定 › 角色誌** 對該角色按 **刪除**。要注意兩件事：

- **這是不可回復的**：該角色底下的成員、他們的對話與角色誌會一起永久移除。
- **有成員線上時刪不掉**：得先讓它下線（見下方「上線與下線」），才能刪。

## 發外包：不用你一個一個開

外包不是你手動「請」進來的。它由**任務手冊**驅動：某一「類」任務在手冊裡被指定「交給外包做、一次跑幾份」，任務進來時系統就臨時開一個外包 worker 去做，做完自動退場解僱。

所以「發外包」你要碰的其實是**任務手冊**：

- 去 **設定 › 任務手冊**，把某類任務的負責對象設成外包，並填 **Hire count（雇用份數）**——同一類要並行跑幾份。
- 誰負責哪本手冊、跑幾份、在哪台機器，**只有你（owner）或你的 admin 助理能設**——那是治理面的設定，一般成員改不了。

任務手冊怎麼建、識別鍵怎麼挑，見 [任務是怎麼運作的](tasks.md)。

### 全域同時雇用上限

外包開太多不會無限燒錢——有一個**全域同時雇用上限**守住：**滿額就排隊，有名額自動接**，不用你逐張催。

在辦公室側欄切到 **Outsource（外包）** 分頁，點最下方 **招攬新成員** 會打開 **外包上限設定**：

| 設定 | 意思 |
| --- | --- |
| 一個數字（**最多雇用 N**） | 同時最多 N 個外包在跑，滿了排隊 |
| **無限**（∞） | 不設上限 |
| **0** | **暫停指派**——現有的跑完就不再開新的 |

分頁標題下的小字會顯示目前人數與上限（例如「3 人 · 上限 5」）。

### 外包名單上看得到什麼

每一列顯示外包的**代號**、**任務類型**、以及它**現在正在做的那張任務的標題**（沒有進行中任務時顯示「無當前任務」）。點一列就開跟這個 worker 的聊天（標題是「外包 · 代號」）；點它的頭像則開**外包詳情**。外包是匿名的，所以名單上不寫模型、不寫識別鍵——代號本身已經隱含了它用哪個模型。

## 每位成員的個人頭像

你（owner）可以在**正職成員詳情**或**外包詳情**替該成員上傳、替換或移除個人頭像；一般成員不能替自己或別人修改。支援 PNG、JPEG、WebP，檔案上限為 64 KiB。選到不支援或太大的檔案時，畫面會直接說明原因；server 也會再次驗證，不會只相信瀏覽器。

個人頭像會出現在名冊、聊天、任務、請示、詳情與監控等主要身分位置。它只改變「這是誰」的圖片，不取代名字旁的 presence 圓點。顯示順序是：

1. 個人上傳的圖片；
2. 角色／主題的既有圖片；
3. 內建圖示。

所以移除個人頭像、舊資料沒有頭像，或圖片載入失敗時，都會安全回到原本的顯示，不會留下破圖。頭像綁定的是成員那個穩定的 id，不會因為改名而換到別人身上。

## 上線與下線

成員在不在線上，只由名字旁那顆 **presence 圓點**表示（顏色是唯一訊號）：

| 圓點 | 意思 |
| --- | --- |
| **Offline（離線）** | 沒在跑 |
| **Waking（喚醒中）** | 剛被叫醒、還在開機 |
| **Online（線上）** | 已就緒，可以對話 |
| **Stopping（停止中）** | 正在收尾退場 |
| **Stopped（已停止）** | 已停下 |

「線上」在 OffiCraft 裡有一個很乾淨的定義：**成員此刻有沒有持著那條到 server 的長連線**——持著就是線上，斷了就是離線，沒有心跳、沒有 TTL。背後的道理見 [架構與運作原理](architecture.md)。

**你能做的幾個動作**（成員詳情面板 / 外包詳情裡）：

兩個面板上半部的**欄位**都是**唯讀**的：只講「現在實際是什麼」，要改**啟動設定**（執行環境、模型、思考強度、要跑在哪台機器）一律走「喚醒／更改」開的那份設定，**兩邊都是**（沒在跑的時候那顆叫喚醒，在跑的時候叫更改）。下面每一條都標了它出現在哪個面板。

🔵 **「AI 執行環境」你選得動；你沒選的時候，是機器替你選**：可選 **Claude Code** 或 **Codex**，改它一律走「喚醒／更改」開的那份啟動設定。**你只要親手選過一次，那就是定局**——沒有任何機制會蓋掉你選的值。**但新請的成員出生時是「還沒有人選過」**（新增角色帶出來的那位正職是這樣，出廠就有的助理 Mira 也是），那一格要等到它**第一次被派上某台機器**的那一刻才定案：那台機器**當下回報**自己備好了 Claude Code，就是 Claude Code；只備好 `codex`，就是 **Codex**。定案的同時寫在這位成員身上，之後不會再重算。（兩個都沒備好，系統**不猜**——它不會把一個猜出來的值寫死在這位成員身上。⚠️ 但**它也不會擋下這次上線**：那一格留白、照舊當成 Claude Code 送出去，於是你看到的會是它起不來、卡在 Waking，原因要到「最近操作」那一行才寫得出來。）

⚠️ **所以「請一個人」的結果會跟機器當下的狀態走**：同一份「招攬新成員」，落在裝好 Claude Code 的機器上長出來的是 Claude Code 成員，落在只裝了 `codex` 的機器上長出來的就是 Codex 成員。**這是刻意的**——它讓一台只有 `codex` 的機器不必為了請人先去補裝一個 Claude Code。代價是：**光看你送出的那份請求，預測不出會得到哪一個**。要它一定是哪一個，就在啟動設定裡自己選一次。

⚠️ **還沒定案之前，啟動設定裡那一格會先顯示「Claude Code」——那是版面上的填充值，不是已經決定了。** 這個填充值**不會**被你送出去：原封不動按確認不會（三個啟動欄位都沒動的話，根本不會送出啟動設定），**在同一份設定裡只改「模型」或「思考強度」也不會**——只有你**真的把那一格改成別的值**，執行環境才會被存下來。所以在只裝了 `codex` 的機器上調模型或思考強度是安全的，不必為了保險順手去選執行環境。

（**代價**，講在前面免得你以為是壞掉：正因為「照著螢幕上再選一次 Claude Code」跟「根本沒選」在畫面上長得一模一樣，這份設定**沒辦法讓你刻意把一位還沒定案的成員釘成 Claude Code**。真的要釘，先選 Codex 送出、再改回 Claude Code；或者就讓它自動定案——只要那台機器備好了 Claude Code，結果本來就是 Claude Code。）

⇒ 一台**只裝了 `codex`** 的機器上有人起不來時，該做的是把這個欄位改成 Codex，不是再去裝一個 Claude Code；照著做的步驟見 [常見問題與排解](troubleshooting.md) 的〈出廠的 Mira 起不來，而這台機器只裝了 `codex`〉。（面板上半部那一格顯示的是**成員回報過什麼**，不是你剛設的值——各欄位的規矩見 [介面說明](interface.md)。）

⚠️ **「唯讀」只講到這裡為止**：面板往下捲還有可以**就地編輯**的展開區塊，它們設的不是啟動設定、也不經過喚醒／更改——**Scheduled messages（定期訊息）**〔正職面板 / 外包詳情，**兩邊都有**〕與 **Webhook endpoints（Webhook 端點）**〔**只有正職面板有**〕。兩者的欄位對照見 [介面說明](interface.md)。

- **Wake（喚醒）**〔正職面板 / 外包詳情〕 — 把一個離線 / 已停止的成員叫回線上。按下去會先打開一份**啟動設定**（執行環境、模型、思考強度、要跑在哪台機器），確認後才啟動——這一次的設定就是它起來時用的。**四個欄位一開始都預設成它原本的那一組**，你只改想改的那個就好；特別是機器，就算你釘的那台正在睡，它也**還是留著那一台**，不會被偷偷換到別台。外包詳情的這顆是同一套（**四個欄位連名字都一樣**，外包那邊也叫「思考強度」）——舊版外包按下去是**直接**照原設定重派、什麼都不問，現在一律先問再送。⚠️ **它「還在跑」的時候按下去，現在什麼都不會發生，而這是刻意的**（owner 2026-09-06 裁定「正在跑就不動它」）：舊版會**當場把那一手 session 砍掉**再重派，等於連它寫到一半、還沒交回來的東西一起丟；現在按下去只是把「我要它在線上」記下來，**不動它、不殺它**，它手上的收尾、加速停止、換手全部照跑，「最近操作」那格會寫一句話告訴你這次什麼都沒送。**真的要把卡住的那一手結束掉，是兩顆：先「強制停止」，再「喚醒」。**另外，**收尾中（正在停止）的外包按喚醒，它還是會回來**——只是不再是當場回來：等它自己把收尾做完，系統下一輪就會把它重新起起來。就算它現在離線，你也可以先在聊天框留言，**訊息會排隊，它上線就讀到**。
- **Change（更改）**〔正職面板〕 — 成員**線上**時，喚醒的位置換成這顆鍵（右上角，跟**停止**左右並排），打開的是**同一份**啟動設定：四個欄位一起改、一次確認送出。**多數情況不是按了就換**——線上而且手上還有沒交回的狀態時，系統會先開一個優雅收尾窗，等它收完這一手才在下一手套用（只換一輪手，不是砍掉重開）；若這一輪的收尾**已經收攏過**，那就當場執行。換機器的話，面板會照常顯示它**現在**在哪台，旁邊掛一個「→ 要換到 ○○」的過渡標示，換完自動消失。
- **Change（更改）**〔外包詳情〕 — 外包**工作中**時，喚醒的位置換成這顆鍵，打開的是**同一份**設定（執行環境、模型、思考強度、要跑在哪台機器），一次確認送出。**改模型／執行環境／思考強度**跟**換機器**走的是**同一條收尾漏斗**：**多數情況不是按了就換**——它**在線上、而且手上還有沒收完的狀態**時，系統會先開一個優雅收尾窗，等它自己回報收完（或你按**加速停止**）才在下一手套用新值；這段期間**不砍它、也不派新的一手，沒有倒數**，但它會收到一則「該收尾了」的預告。**強制停止不會有下一手**——那顆是當場砍掉、**不重生**，你存下的新值要等它之後**被重啟／喚醒**才會生效。你按過**停止**的（**已停止**），兩種改法都只存不啟動，要等你**重啟**它才會帶著新值起來。其餘情況——這一輪收尾**已經收攏過**，或它**不在線上**（含**已指派**、還沒上工的）——就不用等：**換機器會當場把它派到你選的那台**；改模型／執行環境／思考強度則**只有在它工作中而且在線上**時才會當場換一手，否則只是先存起來、**下次啟動時生效**。**沒有**「只儲存，不喚醒」那顆鍵——正職有，外包沒有，因為外包的換機器不是單純改釘選、它會順手把人重新派出去，所以一顆說「存了但沒啟動」的鍵對外包會是假話。
- **只儲存，不喚醒**〔正職面板〕 — 成員**離線或已停止**時（喚醒中的不算，那時按確認就是啟動），那份啟動設定裡多一顆這個鍵：**只把設定存起來、不啟動它**。用在「先把模型／機器調好，等要用的時候再喚醒」——存好的設定會在下次喚醒時採用。
- **Refocus（重新聚焦）**〔正職面板 / 外包詳情〕 — 線上時可用。按下後成員會壓縮記憶、收尾這一手 session、重生成新的一手接著跑。**任務不會因此被關掉**，只是換了一手更清爽的記憶。（這是你主動觸發一次「換手」；系統也會在記憶快滿時自動換手，門檻在 設定 › 參數調整 調，見 [設定與參數](settings.md)。）
- **Stop（停止）**〔正職面板 / 外包詳情〕 — 讓成員正常收尾後停下。它是**請它收工**，不是砍掉：它會被帶到〈停止〉那份文件、自己收完再回報，**沒有倒數**，所以要等多久由它手上的東西決定。兩個面板的這顆都在右上角、跟**更改**左右並排。**一開始只有這一顆**（owner 2026-08-21「不是一開始就顯示三個按鈕」「按了才出現」）：**加速停止**要等到這個成員真的**進入軟下線**才長出來，**強制停止**要等到那場收尾**被放上時鐘**才長出來，還沒輪到的那一顆是**不存在**，不是變灰。已經按過的**停止**不會被拿掉——它留在原位變灰，所以新長出來的那顆一定落在**右邊的新位置**，不會遞補到手指剛剛按的地方；而且**剛出現的那顆有短暫一段不能按**，連按兩下沒辦法替你往上升一級。**收尾期間那一排不會消失**，因為在一個沒有死線的等待裡，它們是唯一能結束等待的東西。外包在 2026-08-21 之前按下去是**當場砍掉**，現在跟正職同一套。
- **Accelerated stop（加速停止）**〔正職面板 / 外包詳情〕 — 已經在收尾的成員，給它一個**明確的死線**並且**告訴它**。要**已經在軟下線裡**才有東西可以加速——不限於你親手按的**停止**，**記憶第一段門檻**系統自己開的那一場換手也算（owner 2026-08-21「已經觸發軟下線的人可以被觸發加速下線」）；不在裡面的成員根本不會出現這顆，直接打端點則會被擋下來並告訴你該先按哪一顆。它不是砍掉，成員仍然可以提早收完；秒數在 設定 › 參數調整 調。
- **Force stop（強制停止）**〔正職面板 / 外包詳情〕 — 立刻砍掉 session、跳過正常收尾，而且**什麼都不跟它說**（它馬上就不存在了，說了也沒有人聽）。**進行中還沒存的工作會遺失**，是最後手段，所以三顆裡只有這顆會再問你一次。

> **外包做完之後**：任務一結案，那個外包就**釋出離隊**，從左欄名單消失。它的東西不會不見——聊天紀錄還在，從舊訊息的「跳到原訊息」或從舊連結開它的詳情，**兩邊都會告訴你同一句話：這個外包已結案釋出，你看到的是唯讀的歷史紀錄**。已離隊的外包沒有「喚醒／更改／停止」——它的任務已經結束了，那些動作沒有對象。

> **EFFORT · Thinking（思考強度）**〔正職面板 / 外包詳情，**同名**〕— 這個成員的推理強度（低／中／高／極高／最高）。在上面那份設定裡改；正職改了之後**下次喚醒或換手時生效**，外包則是**工作中先收尾這一手、在下一手套用，已指派的下次啟動才套用**。

畫面上每個欄位更完整的對照，見 [介面說明](interface.md) 的「成員與外包」一節。
