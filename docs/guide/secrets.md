# 把帳號金鑰交給成員用（密鑰）

讀完這頁，你能把 API token、部署金鑰這類機密存進 OffiCraft，讓成員在需要時取用，而值不會出現在聊天、請示卡或任務紀錄裡。

## 密鑰怎麼運作

密鑰存在 server 上，每一筆有 ID、名稱、值和備註：

- **ID**：`sec-` 開頭的固定編號，由 server 產生。成員取用時以 ID 指定。
- **名稱**：給人看的標籤，可以重複，最多 128 字。
- **值**：機密本身，最多 65536 字。存入後控制台不會再顯示。
- **備註**：寫給成員看的使用注意事項（選填），例如「只用於發布到 npm，不要拿來推 git」。

只有你能新增、修改和刪除密鑰。所有在職的 AI 成員（正職與外包）都能取用，取用一律透過 `ocagent secret` 指令，值只會交給指令的環境變數或寫進權限為 0600 的檔案，不會印出來。你自己在控制台和 API 上都讀不回值。

## 新增密鑰

1. 點上方導覽列的「密鑰」分頁。
2. 按「新增密鑰」。
3. 填「名稱」與「值」，需要時填「備註」。
4. 按「儲存」。

儲存後清單多出一張卡片，顯示 ID、名稱、備註（沒填就不顯示）、最後存取和最後更新時間。點 ID 會複製「密鑰 ID」，方便貼給成員。

## 修改與刪除

- **修改**：按卡片右上角的編輯圖示。值欄留空＝保留原本的值；要換值就把新值完整填一次。只改名稱或備註時，值留空即可。修改不會重設最後存取時間。
- **刪除**：按卡片右上角的刪除圖示並確認。刪除後無法復原，之後成員用該 ID 取用會失敗。

## 交代成員使用某一筆密鑰

在聊天或任務裡告訴成員要用哪一筆。最明確的方式是直接給 ID，例如：

> 用密鑰 sec-aaaaaaaaaaaa 發布這個套件到 npm。

沒給 ID 時，成員會依名稱和備註找出對應的該筆；判斷不出是哪一筆時，會開請示卡請你指定。成員使用前會先讀備註，所以有使用限制就寫在備註裡。

不要把值直接貼在聊天裡。聊天內容會留在紀錄中，也會被帶進成員的記憶。

## 成員端的 `ocagent secret` 指令

成員在自己的 session 裡用 `ocagent secret` 取用密鑰。四個子命令都不會印出值：

| 子命令 | 用途 |
| --- | --- |
| `ocagent secret list` | 列出所有密鑰的 ID、名稱與備註 |
| `ocagent secret show <ID>` | 顯示一筆密鑰的 ID、名稱與備註 |
| `ocagent secret run --env 變數=<ID> -- 指令` | 把值放進環境變數後執行指令；指令輸出中出現的值一律顯示為 `***` |
| `ocagent secret write <ID> --file <路徑>` | 把值寫進一個權限為 0600 的新檔案，給只能從檔案讀憑證的工具使用 |

例如：

```
ocagent secret run --env NPM_TOKEN=sec-aaaaaaaaaaaa -- npm publish
```

`run` 一次最多指定 16 筆不同的密鑰；只要有一個 ID 不存在，指令就不會執行。`write` 預設不覆蓋已存在的檔案。各子命令的完整參數與結束碼，可在成員的 session 裡執行 `ocagent secret --help` 查看。

## 最後存取時間

卡片上的「最後存取」是成員最後一次成功取得值的時間，也就是最後一次 `run` 或 `write` 成功的時間；`list` 和 `show` 不取值，不會更新它。從沒被取用過的密鑰顯示「尚未使用」。

用途：

- 確認成員真的用了你交代的該筆。
- 找出很久沒人用的密鑰，考慮刪除。
- 發現不該被用到的密鑰有最近的存取時間時，到對應的服務撤銷並換新那把金鑰，再回 OffiCraft 更新值。

## 備份 vault.key

密鑰的值用資料目錄裡的 `vault.key` 加密，資料庫備份不包含它，請另外保存；少了它，還原後的密鑰無法取用。保存、還原與遺失時的處理見 [保護你的工作室](security.md) 的「密鑰與 vault.key」。
