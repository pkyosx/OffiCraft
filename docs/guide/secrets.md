# 把帳號金鑰交給成員用（密鑰）

讀完這頁，你能把 API token、部署金鑰這類機密存進 OffiCraft，讓成員在需要時取用，而機密的內容不會出現在聊天、請示卡或任務紀錄裡。

## 新增密鑰

到上方導覽列的「密鑰」分頁新增，填名稱與值。有使用限制時，寫在備註，例如「只用於發布套件，不要拿來做別的事」。

每一筆密鑰都有一串 `sec-` 開頭的密鑰 ID，可以複製下來給成員。

**值存進去之後，控制台不會再顯示。** 你自己在控制台上也讀不回原本的值。

只有你能新增、修改和刪除密鑰。所有在職的成員，正職和外包，都能取用。

## 交代成員使用某一筆密鑰

在聊天或任務裡告訴成員要用哪一筆。最明確的方式是直接給密鑰 ID，例如：

> 用密鑰 sec-aaaaaaaaaaaa 發布這個套件到 npm。

沒給 ID 時，成員會依名稱和備註找出對應的那一筆；判斷不出來時，會開請示卡請你指定。成員使用前會先讀備註，所以有使用限制就寫在備註裡。

**不要把值直接貼在聊天裡。** 聊天內容會留在紀錄中，也會被帶進成員的記憶。存成密鑰後，成員取用時值不會顯示出來。

## 修改與刪除

- **修改**：可以改名稱、備註，或換一個新值。
- **刪除**：刪除後**無法復原**，成員之後用這筆密鑰 ID 取用會失敗。

## 看密鑰有沒有被用過

每一筆密鑰都會顯示「最後存取」，也就是成員最後一次取用的時間。用途：

- 確認成員真的用了你交代的那一筆。
- 找出很久沒人用的密鑰，考慮刪除。
- 發現不該被用到的密鑰最近有人取用時，到對應的服務撤銷並換新金鑰，再回 OffiCraft 更新值。

各欄位的說明見 [介面說明](interface.md) 的「密鑰」；成員怎麼取用，見 [架構與運作原理](architecture.md) 的「成員怎麼取用密鑰」。

## 換電腦時要帶走 vault.key

密鑰的值是用一個叫 `vault.key` 的檔案加密的。平常不需要你處理；只有把資料庫備份搬到別台電腦時，要連同 `vault.key` 一起帶過去，因為備份裡不包含 `vault.key`。詳細說明見 [保護你的工作室](security.md) 的「密鑰與 vault.key」。
