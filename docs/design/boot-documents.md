# 事件程序文件 — 機制規格

> **owner(Seth) 2026-08-20 定案、2026-08-22 補三則裁定。** 本文件是「送到 agent 眼前的每一句話，都要住在 owner 編輯得動的文本裡」這件事的 **logical spec**：文件怎麼組裝、怎麼切、變數怎麼跑、寫入面擋什麼、還原出廠是什麼。程式與本文不合時 flag owner 定奪。
>
> 🔴 **本文件刻意不列舉「現在有哪幾份文件」。** 那種清單一定會過期，而且**不會有任何東西紅**——這個 repo 已經有數個實例：spec 散文裡列的文件種類漏掉了後來才上線的那一種，票面甚至引用過一個從來不存在的檔案。要知道有哪幾份，問 `list_boot_docs`（`GET /api/boot-docs`），它是從服務這些文件的同一張表算出來的，不可能對一份存在的文件說謊。

## WHY — 要解決的根本問題

owner 讀遍座艙上的〈下線程序〉，找不到 `restart_self` 這個字。那個字在**包住那份文件的那一行 Go 字串**裡：文件他改得動，夾住文件的句子他改不動、也看不到。同一個形狀在 lifecycle 的每一類事件上重複出現。

他的裁定（逐字）：

> 「唯一需要 hardcode 的是變動的數值⋯⋯剩下的訊息應該全部回到可編輯的文本中」
> 「第一行說明可以是固定的不能修改的**也會顯示在 UI 上**，因為有變數的部分通常就是說明發生什麼了，我們會需要修改的通常是接下來他應該採取什麼步驟」

⇒ **碼裡只留算出來的值**（死線的時刻、context 百分比、任務編號）；**那些值出現的句子本身也是文件的一部分**，只是放在一個 owner 看得到、誰都改不動的格子裡。

## 一、一份文件是什麼

一份文件由一個 **`kind` ＋ `key`** 定址。`kind` 是這份文件的種類，也是它在版本紀錄裡的系列名；`key` 是同一種類裡的哪一份。多數種類只服務一個 key；服務多個的種類，是因為那些文件**真的不一樣**（兩份啟動程序的第 3 步互相矛盾，送錯那一份，agent 不會報錯，它只是永遠開不完機）。

所有種類寫在**一張表**（`bootDocRegistry`）。每一列回答這個種類的全部問題：有哪些 key、每個 key 的出廠種子檔是哪個、cap 從哪個設定讀、拒絕訊息怎麼稱呼它、允許哪些變數、要不要切唯讀區、渲染時兩半怎麼接、以及**是不是唯讀**。

> 🔴 **為什麼是一張表而不是一堆 switch。** 這是量過的：上一次新增一種文件，要改**六個檔案裡八個各自維護的 switch 與清單**，其中**四個完全沒有閘**——少寫一臂會編譯過、回 200、然後顯示錯的文字或什麼都不顯示。從一個 slice 解析出來的種類，不可能「在解析那一面存在、在版本紀錄那一面不存在」。

## 二、組裝：種子 ⊕ 覆蓋

每一份文件都有兩層：

- **出廠種子**：編進 binary 的 `seeds/*.md`。**永遠不會被寫入面改到。**
- **覆蓋（overlay）**：owner 的編輯，存在 DB。

讀取時折疊：有覆蓋就給覆蓋，沒有就給種子。回應同時帶兩個**回答不同問題**的旗標——`is_default`（有沒有人編輯過）與 `has_seed`（有沒有出廠版可以回去）。前者說你手上這份是不是原廠，後者是「還原出廠」這個動作的前提。

種子永遠不被覆寫，是「還原出廠」能成立的唯一理由：那條路不依賴任何編輯器可能弄壞的東西。

## 三、切法：唯讀區與本體

文件內文裡可以有**一行 marker**。marker 以上是**唯讀區**，以下是**本體**。

| | 唯讀區 | 本體 |
|---|---|---|
| 說什麼 | 發生什麼事 | 接下來要做什麼 |
| 誰寫的 | 程式（送出時填值） | owner |
| 可以有變數嗎 | 可以 | **一個都不行** |
| 改得動嗎 | 改不動 | 改得動 |
| 看得到嗎 | **看得到** | 看得到 |

**為什麼是文件裡的一行，而不是 wire 上的第二個欄位**：owner 要**看到**他改不動的那一半，而且要看到**模板原文**（含變數名）——這張票之所以存在，就是因為他去文件裡找一個字而那個字不在文件裡。一行 marker 讓兩半出現在他本來就在讀的同一個編輯框裡，而且對 wire 契約零成本。

marker 是一個**完全相等的整行**，不是模糊比對。模糊的邊界（「任何一行破折號」）會讓 owner 不小心造出第二道牆，而他的編輯被擋在哪裡會跟著默默移動。

**讀者看不到 marker**：送出前一律走渲染，marker 消失，兩半用**這份文件自己的接法**接起來。接法是逐份的、而且不是裝飾：今天的送出端真的有三種形狀（開機脈絡用空行接、下線通知用單一換行把文件貼在句子底下、任務通知讓兩半在同一段裡連著跑）。把它們統一渲染，會**默默改掉**至少兩種文件送到 agent 眼前的樣子。

⚠️ **「通常」不是「總是」。** 有些文件的變數落在指示句的**中間或尾巴**，對它們而言「唯讀區是前綴」與「本體零變數」不可能同時成立，除非移動位元組——而移動位元組是內容改動。這種文件**整份不切**，並且把衝突留給 owner 裁，不由執行者猜。猜的失敗模式是事後沒有人看得出來的那一種：文件讀起來很順，但它不再說原本說的話。

## 四、變數：宣告、驗證、渲染

一個名字會經過三道：

1. **宣告** — 每個種類列出它可以用哪些名字。
2. **驗證** — 寫入面拒絕任何沒宣告的名字。
3. **渲染** — 送出時，宣告了卻沒有值的名字**讓送出失敗**，不會代換成空字串。

語法是 `{名字}`。

三道各自擋掉一種失敗，而在這套機制之前，**三種失敗都沒有任何地方會紅**：這棵樹先前對 owner 可編輯的文件**完全沒有插值也沒有驗證**，一份用了程式不會填的名字的文件，會帶著大括號原封送到 agent 眼前，而任何一個介面都不會吭一聲。

**沒有值時拒絕、而不是填空白**，理由是失敗的方向：帶著 `{task_no}` 的句子看起來就是壞的；被「修好」成空字串的句子**讀起來完全正常，只是指到錯的東西**。

**沒有宣告 ≠ 宣告為空**。前者是這個種類**完全不驗證**（有文件的內文本來就含 JSON 範例，這個語法分不出它和變數的差別，為了替新文件加閘而弄壞今天在跑的文件，是划不來的交換）；後者是驗證、且一個都不准。

## 五、寫入面擋什麼

寫入是**整份取代**，不是追加。四道閘，每一道都說「什麼都沒寫進去」——因為 owner 的編輯框裡有一整篇東西，他需要知道要不要重打：

| 擋什麼 | 回什麼 | 為什麼 |
|---|---|---|
| **唯讀文件** | 405 | 這份文件顯示是為了讓人看見 agent 被告知什麼，**沒有任何 principal 能改它**。所以講的是「這份文件是什麼」，不是「你缺什麼權限」——講權限會害讀者去找一個不存在的角色開通。 |
| **動到唯讀區**（含把 marker 整行拿掉） | 400 | 沒有邊界的文件，就沒有唯讀的那一半了。 |
| **本體出現變數** | 400 | 本體是 owner 打字的地方；那裡的名字沒有人填。 |
| **超過 cap** | 400 | 回應要告訴你：你寫了多少、上限多少、現在存著多少。 |
| **清空** | 400 | owner 裁定（`rc-a2dab0f20eea`）：清空就拒絕，並明說沒寫進去。**「清空＝還原出廠」是他明確沒選的那條，不得偷偷實作。** 代價他知情：要讓某一類事件不發通知，得另外做一個明講的開關，不能拿清空當靜音。 |

cap 是**逐份**的，而且有些文件共用同一個設定——回應裡那個數字永遠是**即將判你這一次寫入**的那個。

## 六、還原出廠

還原是把覆蓋**做成墓碑**，讓折疊掉回種子。它是冪等的。

**這條路不套用任何長度上限**：出廠文字是產品的一部分，沒有任何設定可以擋住回去的路。這正是它作為**復原路徑**的意義——當一次壞的編輯已經讓 agent 開不了機時，這條路必須只靠座艙就走得通，路徑上不需要任何活著的 agent、也不需要任何 MCP client。

被丟掉的那份覆蓋會留在版本紀錄裡，所以**還原本身也是可以還原的**。

沒有出廠版的文件（`has_seed=false`）在這條路上是 404：沒有東西可以回去，這是誠實的「這裡沒有」，不是一個要繞過去的洞。

## 七、版本紀錄

每一次寫入（取代與還原都算）都把被換掉的那一版留進版本紀錄，用同一組 `kind`／`key` 定址。**沒有改變任何東西的儲存不留版本。**

版本紀錄的還原是**第三個寫入面**，而且是唯一一個**繞側面**碰到文件的：它直接寫覆蓋列。所以唯讀的判定必須在那條路上也成立——只住在取代那支函式裡的閘，是這條路走得過去的閘。

## 八、誰讀得到、誰改得動

- **讀**：機器層。agent 本來就在讀這些文件（開機折疊就把它們交到它手上），所以這裡沒有任何新東西給它。
- **寫與還原出廠**：助理層（owner 或 admin 助理）。這些文字會落進**每一個** agent 的開機脈絡、或是它被收走時收到的那一則通知；壞掉的那一份是所有人都讀到、而沒有人會回報的——**開不了機的 agent 不會在那裡告訴你它開不了機**。

**每一份文件的授權底線都一樣**，沒有任何一份跟別份不同。這就是端點做成泛型的理由：一組 `{kind}/{key}` 路由服務全部，而不是每份三個具名端點——後者的代價是每個 agent 的工具清單永久膨脹，為的是多數 agent 一輩子不會碰的文件。

⚠️ **唯讀不是授權底線的一格**。沒有任何 principal 過得了它，把它寫成路由上的 `requires` 等於宣告一個沒有人擁有的階級。它住在寫入路徑上，那裡才說得出「這份文件是什麼」。

## 九、送出端

文件是**送出端去讀**的，不是 agent 自己回頭抓的。送出端的責任有三件：

1. 取**渲染過**的文字（marker 不能到 agent 眼前）。
2. 供齊這份文件宣告的每一個變數的值。
3. 拿不到文件時**降級**，不要靜默：少了檢查清單還活得下去，少了通知不行。

有一種送出端會自己在 Go 裡組出唯讀區那一句，然後把**本體**貼在底下——那種情況要的是本體、不是整份渲染，否則唯讀區會印兩次，一次填了值、一次還帶著大括號。

## 取代了什麼，以及還沒取代什麼

在這套機制之前：這些句子是 Go 字串相加；座艙上沒有入口；沒有插值、沒有驗證；同一句話要改就得改碼，而改碼的人不是 owner。

🔴 **機制與送出端是兩件事，今天只有一部分接上了。** 開機折疊的那幾份與〈下線程序〉真的走這條路；其餘幾份**文件存在、可編輯、有版本紀錄，但送出端還在用程式裡的舊字串** —— `RenderDocVars` 在生產碼裡目前沒有任何呼叫端。所以本文件描述的是**機制**成立的範圍，不是「每一句話都已經走這條路」。

**這個狀態自己有一個危險**：owner 在座艙上編輯一份還沒接線的文件，會拿到 200、會多一筆版本紀錄，而 agent 收到的字沒有變，**沒有任何介面告訴他**。接線落地之前，這件事只有這一段文字擋著。
