# 背景

控制台只接受跑控制台那台電腦本身的連線（`127.0.0.1`）。要從手機或其他地方的裝置打開控制台，要在那台電腦上執行轉發工具，把外部的 HTTPS 連線轉到控制台的埠。

這類任務只做轉發這一件事：安裝與設定轉發工具、讓它開機後自動執行、讀回網址可以打開。不改控制台的設定、不改路由器或防火牆，也不替使用者登入任何帳號。

需要管理員權限（`sudo`、輸入電腦密碼）或使用者本人登入帳號的動作，一律開 action Reply Card，寫明要執行什麼、做完會看到什麼，請使用者執行；使用者回覆後讀回結果再繼續。不要求使用者把密碼或帳號憑證交給成員。

轉發方式有三種，依使用者有沒有 Cloudflare 帳號與網域、這台電腦的 cloudflared 是否已經給其他網址用，以及手機要不要免裝 App 決定（見第 3 步）：

- **cloudflared**：固定的公開 HTTPS 網址，手機不用另外裝 App，任何知道網址的人都打得開登入頁。需要使用者在 Cloudflare 上已經有帳號與自己管理的網域。
- **Tailscale（只限自己的裝置）**：只有登入同一個 Tailscale 帳號的裝置連得到，不需要網域。使用者要在電腦和手機上各登入一次 Tailscale。
- **Tailscale Funnel**：把 Tailscale 給的 `ts.net` 網址公開到網際網路，手機不用裝 App，任何知道網址的人都打得開登入頁。不需要網域，但電腦要登入 Tailscale 一次。

# SOP

## 1. 確認執行環境

轉發工具必須裝在跑控制台的那台電腦上。自己的伺服器網址（`OC_BASE`）是 `127.0.0.1` 或 `localhost` 時，所在機器就是跑控制台的機器；從同一個網址讀出控制台的埠號。

不在那台電腦上時，停止執行，開 Reply Card 告訴使用者這件事要由那台電腦上的成員處理，請使用者決定改派給誰。

同時確認這台電腦目前的轉發狀態：`tailscale serve status`；cloudflared 是否在執行、預設設定檔（`~/.cloudflared/config.yml`）存不存在與裡面有哪些網址；cloudflared 是否開機自動執行，看實際的啟動設定（macOS 的 `~/Library/LaunchAgents` 與 `/Library/LaunchDaemons`、Linux 的 systemd 服務），不只看有沒有用 `cloudflared service install` 裝過。已經有指向控制台的轉發時，仍然先做第 2 步；第 2 步通過後，確認轉發已設成開機後自動執行（沒有的話照第 4 步補上），再到第 5 步讀回網址。已經有的轉發是 Cloudflare 的臨時網址（`trycloudflare.com`）時不沿用，照第 3 步重新決定。

用 `list_machines` 看工作室有沒有其他機器。其他機器的 warden 連的是加入工作室時用的網址，通常就是目前的轉發網址；轉發關掉或網址改變時，那些機器與上面的成員都會斷線。

**完成條件**：步驟備註寫下控制台的埠號、所在機器就是跑控制台的機器、目前有沒有轉發（有的話附網址），以及工作室的其他機器。

## 2. 安全檢查

轉發開通後，拿到網址的人都打得開登入頁並試著登入，所以開放前一定要有兩步驟驗證。通行密鑰不能取代兩步驟驗證：有通行密鑰時，登入頁仍然可以只用密碼登入。

用 `get_login_protection` 讀登入保護狀態：

- **兩步驟驗證已開啟**：繼續。
- **兩步驟驗證沒開**：開 action Reply Card，請使用者到控制台右上角頭像 › 帳號安全 › 兩步驟驗證開啟。使用者回覆後再讀一次；仍然沒開，再開卡說明讀到的結果並請使用者開啟。使用者表示不開啟時，不設定轉發，在任務上寫明原因後結束任務。第 1 步發現已經有轉發時，在卡上寫明控制台目前已經對外開放、只靠密碼保護，並提供關掉轉發的選項；有其他機器時，卡上列出這些機器，寫明關掉後它們會斷線。使用者選擇關掉時：Tailscale 依 `tailscale serve status` 顯示的設定，只關掉指向控制台埠號的那一條（例如 `tailscale serve --https=443 off`；Funnel 用 `tailscale funnel --https=443 off`）；cloudflared 只在開機自動執行的服務就是控制台這條 tunnel 時執行 `cloudflared service uninstall`；服務帶著其他網址，或控制台的 tunnel 是用其他方式啟動時，開卡說明情況，請使用者決定。關掉後讀回 `tailscale serve status` 已沒有指向控制台埠號的轉發，或 cloudflared 已不在執行，並寫進任務。

請使用者確認兩件系統檢查不到的事：登入密碼不容易被猜到（系統只存密碼的雜湊值，看不出強度），以及是否要把設定 › 參數調整 › 登入有效期調短。兩步驟驗證沒開時放在上面那張卡；已開啟時另開一張卡。使用者表示密碼不夠強時，請使用者到右上角頭像 › 帳號安全 › 修改密碼改好，再繼續。

**完成條件**：`get_login_protection` 讀回兩步驟驗證已開啟，且使用者已在卡上確認密碼。

## 3. 決定轉發方式

開 decision Reply Card，問使用者是否已經有 Cloudflare 帳號，而且有網域交給 Cloudflare 管理；這台電腦有 `~/.cloudflared/cert.pem` 時，代表曾經登入過 Cloudflare，在卡上一併寫出。卡上的選項寫成使用者的情況（有 Cloudflare 帳號與網域／沒有，手機要免裝 App／沒有，手機可以裝 App），轉發方式依使用者選的情況決定；不要把三種方式列成選項讓使用者挑，也不要建議跟下面規則不同的方式。

- **有**：用 cloudflared，同一張卡請使用者提供要用的網域。
- **沒有**：用 Tailscale，同一張卡再問手機與其他裝置要不要免裝 App 就能連：要的話用 Funnel（公開），不要的話用只限自己裝置的 Tailscale。用只限自己裝置的 Tailscale 且有其他機器時，卡上寫明那些機器也要裝 Tailscale 並登入同一個帳號。

第 1 步發現這台電腦的 cloudflared 預設設定檔或開機自動執行的服務已經給其他網址用時，即使使用者有 Cloudflare 帳號也用 Tailscale，並在卡上說明原因：cloudflared 的開機自動執行服務一台電腦只有一個、固定讀預設設定檔，加入控制台會改動使用者原本的設定。

不使用 Cloudflare 不需要帳號的臨時網址（`cloudflared tunnel --url`，網址是 `trycloudflare.com`）：臨時網址不支援 Server-Sent Events，控制台的聊天與請示卡無法即時更新，網址每次重新啟動也會換。

**完成條件**：已確定轉發方式（cloudflared、只限自己裝置的 Tailscale 或 Funnel）；用 cloudflared 時使用者已提供網域。

## 4. 設定轉發

依第 3 步決定的方式設定。需要使用者本人的動作（輸入電腦的管理員密碼、在瀏覽器登入帳號、在管理頁開啟功能）時，照背景的規則開卡請使用者執行。

### Tailscale

1. **安裝**：macOS 請使用者從 Tailscale 官網下載並安裝 Tailscale App；Linux 與 Windows WSL2 執行 Tailscale 官網的安裝指令（需要管理員密碼時開卡請使用者執行）。
2. **登入**：請使用者在這台電腦上登入 Tailscale 帳號。macOS 同時請使用者在 Tailscale App 的設定中開啟「登入時啟動」。Linux 與 Windows WSL2 開卡請使用者執行 `sudo tailscale up --operator=<執行成員的系統帳號>`，之後成員不需要管理員權限就能設定轉發。
3. **開啟轉發**：只限自己的裝置執行 `tailscale serve --bg <控制台埠號>`；Funnel 執行 `tailscale funnel --bg <控制台埠號>`，第一次使用時如果印出網址，請使用者用這個網址在 Tailscale 管理頁允許使用 Funnel，完成後再執行一次。macOS 的 Funnel 需要從 App Store 或 Tailscale 官網下載的 App。macOS 的 Tailscale App 不會把 `tailscale` 指令放進 PATH，指令在 `/Applications/Tailscale.app/Contents/MacOS/Tailscale`，而且 App 要先開著，否則指令會一直等不結束。第一次使用時，指令會印出一個網址，請使用者用這個網址在 Tailscale 管理頁開啟 HTTPS 功能，完成後再執行一次。
4. **讀回網址**：`tailscale serve status` 顯示的 `https://<電腦名稱>.<帳號網域>.ts.net` 就是轉發後的網址；Funnel 要顯示 `Funnel on`。

只要關掉 Funnel、保留只限自己裝置的轉發時，執行 `tailscale serve --bg <控制台埠號>`，會改回只限自己的裝置；`tailscale funnel --https=443 off` 與 `tailscale funnel --bg off` 都會連同只限自己裝置的轉發一起清掉。

`--bg` 的設定由 Tailscale 自己保存，Tailscale 重新啟動後會自動恢復，不需要另外設定開機執行。macOS 上 Tailscale App 與控制台都在使用者登入桌面後才啟動，所以電腦重新開機後要登入桌面，手機才連得到。

### cloudflared

1. **安裝**：安裝 cloudflared（macOS 用 Homebrew，Linux 用 Cloudflare 官網的套件）。
2. **登入**：執行 `cloudflared tunnel login`，請使用者用印出的網址登入 Cloudflare，並選擇要用的網域。
3. **建立通道與網址**：建立一條 tunnel，把使用者提供網域下的一個子網域指到這條 tunnel，在預設設定檔 `~/.cloudflared/config.yml` 寫入這條 tunnel，並把這個網址轉到 `http://127.0.0.1:<控制台埠號>`。
4. **開機自動執行**：執行前再確認一次這台電腦沒有其他 cloudflared 服務；有的話停下，照第 3 步改用 Tailscale。macOS 不加 `sudo` 執行 `cloudflared service install`，裝成登入後自動執行的服務；加 `sudo` 會裝成系統層級的服務，讀不到 `~/.cloudflared` 的設定。Linux 與 Windows WSL2 開卡請使用者執行 `sudo cloudflared --config <設定檔的完整路徑> service install`。

**完成條件**：`tailscale serve status` 顯示轉發指向控制台的埠號，或 cloudflared 設定檔把網址指向控制台的埠號且服務在執行；轉發工具已設成開機後自動執行；步驟備註寫下轉發後的 HTTPS 網址。

## 5. 讀回網址

從這台電腦用轉發後的網址打開控制台，確認回應是控制台的登入頁，不是錯誤頁或其他服務。Tailscale 的網址只有加入同一個帳號的裝置打得開，在這台電腦上讀回即可。Funnel 在這台電腦上讀回只代表 Tailscale 帳號內的裝置連得到，公開網路能不能連要在第 6 步請使用者用沒有連 Tailscale 的手機（行動網路）確認。

讀不回登入頁時，依錯誤訊息修正第 4 步的設定；修不好時，開 Reply Card 說明目前狀態與錯誤訊息，請使用者決定停止，或在第 3 步的條件允許時改用另一種方式。

**完成條件**：用轉發後的網址讀回控制台的登入頁。

## 6. 交給使用者

開 action Reply Card，附上轉發後的網址。

**一定要做**：

1. 用只限自己裝置的 Tailscale 時，在手機安裝 Tailscale App，並登入同一個 Tailscale 帳號。用 Funnel 時，用手機的行動網路、不開 Tailscale，直接用瀏覽器打開網址。
2. 用網址打開控制台，以密碼與兩步驟驗證登入。

**可以順便開啟**（不做也能用）：

- **通行密鑰**：之後在手機上用 Face ID 或指紋登入，不用每次輸入密碼與驗證碼。通行密鑰只能在新增時用的網址使用，所以要在手機上、用這個網址新增（右上角頭像 › 帳號安全 › 通行密鑰）。
- **加到主畫面**：像獨立 App 一樣全螢幕打開。iPhone 用 Safari 的「分享 › 加入主畫面」，Android 用 Chrome 選單的「加到主畫面」。
- **推播通知**：有新訊息或請示卡時收到通知。從主畫面打開控制台，在頭像選單填好「通知信箱」，再點頂端的鈴鐺圖示；iPhone 要先加到主畫面。

同一張卡提醒：電腦關機或睡眠時，手機連不到控制台；用 cloudflared 或 Funnel 時，登入頁與回呼端點的網址會公開在網路上；之後要把其他電腦加進工作室時，要用這個網址打開控制台，再複製安裝指令。

**完成條件**：使用者在卡上回覆手機已能用轉發後的網址登入。

## 7. 更換轉發方式或網址

使用者要換轉發方式（例如 Tailscale 換成 cloudflared）或換網域時，照這一節做。先照第 1 到第 3 步確認環境、安全檢查與新的方式，再開 decision Reply Card 列出會受影響的項目，請使用者確認後才動：

- **其他機器**：列出工作室的其他機器。它們要改連新網址，否則舊轉發關掉後會斷線；重新安裝時，那台機器上的成員會斷線，之後要重新啟動。
- **通行密鑰**：通行密鑰只能在新增時用的網址使用，換網址後要在新網址重新新增。
- **回呼端點**：外部服務（例如 Slack、GitHub）設定的回呼網址要改成新網址；新網址在成員詳情的「回呼端點」卡複製。
- **手機**：加到主畫面的捷徑與推播通知要用新網址重新設定。

使用者確認後：

1. **開新轉發**：照第 4、5 步設定新的轉發並讀回登入頁。舊轉發先不要關，讓其他機器在改連前不會斷線。
2. **其他機器改連新網址**：每台機器開 action Reply Card，請使用者用新網址打開控制台，到「監控」分頁的「機器資訊」，在那台機器名稱的選單選「重新安裝」，複製安裝指令到那台機器的終端機執行。不要用「新增機器」，那會建立一筆新的機器紀錄。使用者回覆後用 `list_machines` 讀回那台機器在線上，再重新啟動那台機器上的成員。
3. **關掉舊轉發**：所有其他機器都改連新網址後，照第 2 步關掉轉發的做法關掉舊的轉發並讀回。
4. **交給使用者**：照第 6 步開卡交付新網址，並提醒重新新增通行密鑰、更新回呼網址與手機上的設定。

**完成條件**：新網址讀回登入頁；其他機器都在線上；舊轉發已關掉並讀回；使用者已在卡上回覆手機能用新網址登入。
