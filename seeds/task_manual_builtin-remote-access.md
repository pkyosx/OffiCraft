# 背景

控制台只接受跑控制台那台電腦本身的連線（`127.0.0.1`）。要從手機或其他地方的裝置打開控制台，要在那台電腦上執行轉發工具，把外部的 HTTPS 連線轉到控制台的埠。

這類任務只做轉發這一件事：安裝與設定轉發工具、讓它開機後自動執行、讀回網址可以打開。不改控制台的設定、不改路由器或防火牆，也不替使用者登入任何帳號。

需要管理員權限（`sudo`、輸入電腦密碼）或使用者本人登入帳號的動作，一律開 action Reply Card，寫明要執行什麼、做完會看到什麼，請使用者執行；使用者回覆後讀回結果再繼續。不要求使用者把密碼或帳號憑證交給成員。

轉發方式有兩種，由使用者選一種：

- **Tailscale（建議）**：只有登入同一個 Tailscale 帳號的裝置連得到，不需要網域。使用者要在電腦和手機上各登入一次 Tailscale。
- **cloudflared**：公開的 HTTPS 網址，任何知道網址的人都打得開登入頁。需要使用者在 Cloudflare 上已經有自己管理的網域。

# SOP

## 1. 確認執行環境

轉發工具必須裝在跑控制台的那台電腦上。自己的伺服器網址（`OC_BASE`）是 `127.0.0.1` 或 `localhost` 時，所在機器就是跑控制台的機器；從同一個網址讀出控制台的埠號。

不在那台電腦上時，停止執行，開 Reply Card 告訴使用者這件事要由那台電腦上的成員處理，請使用者決定改派給誰。

同時確認這台電腦是否已經有轉發在執行（`tailscale serve status`、cloudflared 是否在執行）。已經有轉發時，仍然先做第 2 步；第 2 步通過後，確認轉發已設成開機後自動執行（沒有的話照第 4 步補上），再到第 5 步讀回網址。

**完成條件**：步驟備註寫下控制台的埠號、所在機器就是跑控制台的機器，以及目前有沒有轉發（有的話附網址）。

## 2. 安全檢查

轉發開通後，拿到網址的人都打得開登入頁並試著登入，所以開放前一定要有兩步驟驗證。通行密鑰不能取代兩步驟驗證：有通行密鑰時，登入頁仍然可以只用密碼登入。

用 `get_login_protection` 讀登入保護狀態：

- **兩步驟驗證已開啟**：繼續。
- **兩步驟驗證沒開**：開 action Reply Card，請使用者到控制台右上角頭像 › 帳號安全 › 兩步驟驗證開啟。使用者回覆後再讀一次；仍然沒開，再開卡說明讀到的結果並請使用者開啟。使用者表示不開啟時，不設定轉發，在任務上寫明原因後結束任務。第 1 步發現已經有轉發時，在卡上寫明控制台目前已經對外開放、只靠密碼保護，並提供關掉轉發的選項。使用者選擇關掉時：Tailscale 執行 `tailscale serve --https=443 off`，只關掉控制台這一條轉發；cloudflared 執行 `cloudflared service uninstall`，移除開機自動執行的服務。關掉後讀回 `tailscale serve status` 已沒有指向控制台埠號的轉發，或 cloudflared 已不在執行，並寫進任務。

請使用者確認兩件系統檢查不到的事：登入密碼不容易被猜到（系統只存密碼的雜湊值，看不出強度），以及是否要把設定 › 參數調整 › 登入有效期調短。兩步驟驗證沒開時放在上面那張卡；已開啟時另開一張卡。使用者表示密碼不夠強時，請使用者到右上角頭像 › 帳號安全 › 修改密碼改好，再繼續。

**完成條件**：`get_login_protection` 讀回兩步驟驗證已開啟，且使用者已在卡上確認密碼。

## 3. 請使用者選擇轉發方式

開 decision Reply Card，請使用者選 Tailscale 或 cloudflared，卡片寫明兩者的差別（見背景），建議 Tailscale。選 cloudflared 時，同一張卡請使用者提供要用的網域。

**完成條件**：使用者已選定轉發方式；選 cloudflared 時已提供網域。

## 4. 設定轉發

依使用者選的方式設定。需要使用者本人的動作（輸入電腦的管理員密碼、在瀏覽器登入帳號、在管理頁開啟功能）時，照背景的規則開卡請使用者執行。

### Tailscale

1. **安裝**：macOS 請使用者從 Tailscale 官網下載並安裝 Tailscale App；Linux 與 Windows WSL2 執行 Tailscale 官網的安裝指令（需要管理員密碼時開卡請使用者執行）。
2. **登入**：請使用者在這台電腦上登入 Tailscale 帳號。macOS 同時請使用者在 Tailscale App 的設定中開啟「登入時啟動」。Linux 與 Windows WSL2 開卡請使用者執行 `sudo tailscale up --operator=<執行成員的系統帳號>`，之後成員不需要管理員權限就能設定轉發。
3. **開啟轉發**：執行 `tailscale serve --bg <控制台埠號>`。macOS 的 Tailscale App 不會把 `tailscale` 指令放進 PATH，指令在 `/Applications/Tailscale.app/Contents/MacOS/Tailscale`，而且 App 要先開著，否則指令會一直等不結束。第一次使用時，指令會印出一個網址，請使用者用這個網址在 Tailscale 管理頁開啟 HTTPS 功能，完成後再執行一次。
4. **讀回網址**：`tailscale serve status` 顯示的 `https://<電腦名稱>.<帳號網域>.ts.net` 就是轉發後的網址。

`--bg` 的設定由 Tailscale 自己保存，Tailscale 重新啟動後會自動恢復，不需要另外設定開機執行。macOS 上 Tailscale App 與控制台都在使用者登入桌面後才啟動，所以電腦重新開機後要登入桌面，手機才連得到。

### cloudflared

1. **安裝**：安裝 cloudflared（macOS 用 Homebrew，Linux 用 Cloudflare 官網的套件）。
2. **登入**：執行 `cloudflared tunnel login`，請使用者用印出的網址登入 Cloudflare，並選擇要用的網域。
3. **建立通道與網址**：建立一條 tunnel，把使用者提供網域下的一個子網域指到這條 tunnel，設定檔把這個網址轉到 `http://127.0.0.1:<控制台埠號>`。
4. **開機自動執行**：把 cloudflared 設成系統服務（`cloudflared service install`，需要管理員密碼時開卡請使用者執行）。

**完成條件**：`tailscale serve status` 或 cloudflared 的服務狀態顯示轉發指向控制台的埠號、轉發工具已設成開機後自動執行，且步驟備註寫下轉發後的 HTTPS 網址。

## 5. 讀回網址

從這台電腦用轉發後的網址打開控制台，確認回應是控制台的登入頁，不是錯誤頁或其他服務。Tailscale 的網址只有加入同一個帳號的裝置打得開，在這台電腦上讀回即可。

讀不回登入頁時，依錯誤訊息修正第 4 步的設定；修不好時，開 Reply Card 說明目前狀態與錯誤訊息，請使用者決定要改用另一種方式或停止。

**完成條件**：用轉發後的網址讀回控制台的登入頁。

## 6. 交給使用者

開 action Reply Card，附上轉發後的網址，請使用者在手機上完成：

1. 選 Tailscale 時，先在手機安裝 Tailscale App，並登入同一個 Tailscale 帳號。
2. 用網址打開控制台，以密碼與兩步驟驗證登入。
3. 新增通行密鑰：右上角頭像 › 帳號安全 › 通行密鑰。通行密鑰只能在新增時用的網址使用，所以要在手機上、用這個網址新增。
4. 加到主畫面：iPhone 用 Safari 的「分享 › 加入主畫面」，Android 用 Chrome 選單的「加到主畫面」。
5. 開推播通知：從主畫面打開控制台，在頭像選單填好「通知信箱」，再點頂端的鈴鐺圖示。

同一張卡提醒：電腦關機或睡眠時，手機連不到控制台；選 cloudflared 時，回呼端點的網址也會跟著對外。

**完成條件**：使用者在卡上回覆手機已能用轉發後的網址登入。
