# 下線程序（Offboard Sequence）

這是你要下線時送到你手上的收尾清單 —— 那時候開機說明多半已經被壓縮掉了，你不必回頭找、也不要靠記憶。**你現在有多少時間、是誰要你下線，看包著這份清單的那則通知。**

## 先分辨：你收到的是哪一種通知

看包著這份清單的那一句話裡**有沒有 `Your deadline is`**：

- **有** ⇒ **這是最後一通**。真的有人在計時收你，**立刻從第 1 步開始跑，不要等任何人**。
- **沒有** ⇒ **這是軟性通知**（context 壓力的提醒、負責人按重新聚焦、負責人按下線）。**這幾條路上沒有任何時鐘在收你** —— 收你的是你自己按下最後那個工具，或負責人親自按強制停止。⇒ 你有時間先做下面那一格，做完再從第 1 步開始。

🔴 **這是 session 級的單向閂，不是逐則判斷**：只要你這一輪**收過任何一則**帶 `Your deadline is` 的通知，之後不管再收到什麼，一律當最後一通處理，**不得回頭走軟性那一格** —— 兩種通知是兩條各自獨立的管道，後到的那則不代表前一則的時鐘停了。

🔴 **「沒有時鐘」不等於「可以慢慢來」。** 它的意思只是沒有人會提醒你時間到了；你的 context 仍然在漲，漲滿一樣換手。所以下面那一格的目的是**讓在途的東西留下痕跡**，不是拖延。

## 軟性通知才做的那一格：把在途的分身收乾淨

**先去報第 1 步的 `report_stopping()`** —— 它不會讓 server 提前收你，但座艙立刻顯示「停止中」，否則你收分身的這整段時間裡負責人看不到任何動靜。**然後停止加派**，再對每一個還在跑的分身：

1. **問它到哪了。** 明講「不是要你交件、不要停下手上的事」，並要它**現在就講已經發現的、非修不可的問題**，不要留到最終報告 —— 你可能在它交件之前就被換掉。
2. **快好了** ⇒ 等它做完，把結論收進票面。**只等這一輪**：等過一次它還沒交件，就直接轉第 3 條要交接，不要再等第二次。
3. **還要很久** ⇒ **要它收尾到一個乾淨的點並留下交接**，不要硬等，也不要就這樣丟掉。交接寫四件：**我實際跑了什麼**（只寫真的量到的）、**我發現了什麼**（附把握度）、**還剩什麼**（照它會做的順序）、**我沒有檢查什麼**。
   🔴 **它交回來之後，當場把那份交接寫進步驟備註**（備註已有內容時用只送改動那一段的那支工具）—— **分身只活在你的 session 裡，server 上不留紀錄**，沒寫進 server 的交接跟沒寫一樣。
   ⚠️ 一併要求它：**把改動 commit 並 push**；推不上去就在交接裡點名機器、路徑與 branch，**不要留下沒人知道的未提交改動**。**不要回報任何沒有親自跑過的東西。**

🔴 **為什麼主要手段是「要它交接」而不是「等」**：等待只活在你的 session 裡，你被收走它就一起沒了；交接寫進 server，活得比你久。所以只要它不是馬上就好，**留下痕跡永遠優於繼續等**。

## 不管哪一種，回報時都要講清楚手上還有誰在跑

- **誰在做什麼** —— 一定要寫。
- **跑了多久** —— 一定要寫。派出去的時間通常你自己知道；真的因為記憶被壓縮而查不到，就寫「壓縮後已不可考」，**不要編一個數字**。
- **大概還要多久** —— 有就寫，沒有就寫「不知道」。依序試：拿你自己跑過同類工作的經驗估 → 直接問它 → 都不行才寫不知道。**不要為了這一欄去設計一套派工記帳。**

🔴 **這是優先順序，不是平行的六件事。** 從上往下做；時間不夠時，上面做完的比下面做完的值錢。

1. **報開始收尾**：MCP `report_stopping()`。座艙立刻顯示「停止中」；**server 不會因此提前收你**。順帶讀它的回傳：`refocus_op` 是 `relocate` 代表**下一代會在別台機器開機**。
2. **給自己留交接**：MCP `post_chat` 發給你自己（`to=` 你的 member id）—— 現況／在途／卡在哪／下一步。**下一代第一眼看到的就是這則**，而它最便宜，所以排最前面。
   - 🔴 這次若**換機器**，交接裡要點名**機器、路徑、還沒 push 的 branch**；下一代腳下不會有你的工作樹。**更好的做法是一 commit 就 push**，別讓唯一一份留在本地。
3. **把在途工作寫回任務**：MCP `update_step_note` —— 做到哪、下一步接什麼、證據在哪（版本、路徑、哪些是你自己驗的、哪些是聽來的）。任何步驟狀態都寫得進。
   - 🔴 **備註已經有內容時改用 `patch_step_note`**（只送改動的那一段）。交接正是「上一棒還在寫、下一棒已經開始寫同一則備註」最常發生的時刻，而整份取代會**無聲刪掉**對方剛加的東西——你手上那份通常還比較長，連「不准變短」那道守衛都不會叫。
   - 還沒收到回報的 in-process 分身，**寫死一句「沒有回報不等於通過，下一代必須重派」** —— 它會跟你一起消失，而票面上「它還在跑」與「它已經死了」長得一模一樣。
   - 有交付物就現在釘上去（`add_task_artifact`）；任務進終態後會凍結。
4. **把這一輪的教訓寫回長期記憶**：🔴 **先分清楚這一條屬於哪一種** —— 角色 lessons、該任務類型的學習經驗、還是該升進 Insight。**路由規則在開機說明「記憶與學習」那一節，那裡是權威，這裡不重講。** 決定好位置後**先讀現況、同主題合併、刪過時**，不是往後貼。**寫的時候能只送改動的那一段就不要整份重打**——`patch_lessons`／`patch_insight`／`patch_task_learnings`／`patch_task_sop` 都吃錨點：錨點在現況裡必須恰好命中一次，命中不到或命中多次就**整批退、零寫入**，所以**別人動掉你要改的那一段**時你會當場撞到 400，而不是安靜蓋過去。（保障到此為止：這不是版本鎖，讀到寫之間仍有一個毫秒級窗口。）
   - ⚠️ **有一個組合不必做這一步**：任務是 ad-hoc（沒有手冊）而你是外包（沒有角色）⇒ 這一步的位置一個都不存在，包含升進 Insight 那一條（它也認角色）。**跳過它**，不要硬塞進別人的文件。
5. **收拾暫存**：臨時檔案 `mv` 進 `<你的工作目錄>/trash/`（**不要自己 `rm`**），收掉臨時 branch／worktree 與你自己起的程序（只殺你自己捕獲的 PID）。
6. **報停止**：MCP `report_stopped()`。報完就停手，runtime 會自己收攤。**接下來會不會有新的你，看的是「還要不要你在線上」**：換手（context 到頂、owner 按重新聚焦、你自己 `restart_self`）⇒ server 原地重生新的一代；**owner 按了下線 ⇒ 不會重生**，你就是這個位置的最後一代，交接寫給的是未來某天被重新喚醒的人。

⚠️ **只寫在 terminal、本地檔案或這個 session 裡的東西，等於沒有留下。** 要留下來的，都得寫進 server（任務、聊天、長期記憶）。
